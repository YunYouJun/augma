# 空间工作区：应用与项目的原生地图

状态：第一批本地应用大楼、第二批项目区域已实现；AI 生成环境仍是后续设计。现有 RealityKit 场景继续提供庭院、城市、地标、模拟扫描和锚点。

## 产品目标

让用户把真实的工作入口布置成一张有记忆点的地图。例如「Augma 开发区」中，VS Code 大楼绑定仓库，Chrome 大楼绑定文档和预览网址，资料馆绑定设计文件夹。建筑是一个可点击的入口，也能显示应用是否运行、是否正在前台。用户可以用文字描述想要的环境，再预览生成结果并应用。

核心价值是找回工作上下文：一个项目区域把编辑器、网址、资料和专注计时放在一起。保留 Dock、列表与搜索，打开入口无需在三维空间中行走。工作区与 macOS 的 Mission Control 桌面不是同一概念，首版不创建或控制系统桌面。

## 第一批：本地应用大楼（已实现）

- 用户选择要放进场景的应用。使用 bundle ID 作为稳定标识，名称与图标来自系统；不依赖名称关键词猜测应用身份。
- 用现有 RealityKit 基础几何搭建建筑模板，显示应用图标与名称。模板数量与渲染成本有上限，不需要三维生成服务。
- 通过 NSWorkspace 的运行和激活事件更新灯光、状态标记，避免不断轮询。点击大楼激活已运行应用或启动所选应用；失败时保留入口并显示原因。
- 先展示运行／前台状态；不把整机 CPU、网速冒充某个应用的资源占用。
- 支持固定、位置交换、重命名、移除、撤销上一次移除和重新排列未固定大楼。隐藏沉浸助手后停止渲染，重新唤起沿用同一工作区。

入口为「空间 → 应用街区」。采用 4 × 3 地块，上限 12 座大楼；原生列表提供与三维点击等价的打开操作。应用成功打开后自动隐藏沉浸助手，保留当前会话。

布局以有版本的 JSON 原子写入 `~/Library/Application Support/Augma/application-district.json`。应用级 Store 共享建筑、名称、位置和运行状态；各窗口保留自己的选中项与镜头，主窗口和对应沉浸模式复用同一空间状态。损坏或较新版本文件不会自动覆盖，显式重建先保存原文件副本；写入失败保留内存中的编辑并提供重试，退出前再次尝试保存。

自动化验收覆盖应用稳定标识、位置交换、固定、容量、撤销移除、应用移动与缺失、启动失败、重复点击、迟到回调、共享状态、重启恢复、写入失败和损坏文件保护。本机界面已验证应用选择器展示、VS Code 冷启动、三维大楼点击切换 VS Code / Chrome、运行状态更新、名称与位置保存、固定、移除撤销、重启恢复，以及主窗口和沉浸模式共享布局。

## 第二批：项目区域（已实现）

入口为「空间 → 项目区域」，提供独立的 RealityKit 项目园区，最多 6 个区域，每个区域包含项目文件夹、VS Code 与 Google Chrome 的绑定，最多 10 个 HTTP(S) 工作网址。可命名、交换位置、移除及撤销上一次移除；不会删除项目文件。

- 使用原生文件夹选择器创建区域，保存系统书签；打开时解析并持有访问范围，完成后释放。书签失效、目录缺失或无权访问时要求重新选择，不退回到显示路径打开同名新目录。
- VS Code 通过所绑定安装包中的 CLI，以独立参数传入 `--new-window` 和项目路径；支持路径中的空格和中文，不依赖 PATH 中的 `code`。只启动项目打开命令，不执行项目脚本。Chrome 通过 NSWorkspace 打开固定网址，不读取或改写现有标签页。
- 三维区域点击仅切换选择。用户点击「打开工作区」后，先校验并保存编辑，再依次打开编辑器和网址；每项分别报告等待、打开中、已打开或失败。网址成功表示浏览器已接受打开请求，不等于网络页面加载成功。
- 重复点击不会启动并行批次，部分失败可仅重试失败项；重新绑定失效文件夹后可继续重试，并保留已成功的网址结果。取消只停止后续请求；已经交给系统的打开操作不会回滚。迟到的完成结果不会重新创建已删除的区域。
- 项目配置保存到 `~/Library/Application Support/Augma/project-regions.json`，与第一批应用大楼配置分开。采用版本校验、原子写入、保存失败重试，以及损坏文件备份后显式重建。未提交的编辑留在共享 Store，窗口和沉浸模式交接不会丢失；退出前尝试保存，有无效编辑或写入失败时提示返回修正。
- 应用级 Store 共享配置、编辑草稿和打开结果；窗口级空间 Store 保留所选区域与镜头，主窗口和对应沉浸模式共享同一份空间状态。全部入口打开成功后自动收起沉浸助手；有失败项时保留结果面板。

自动化验收覆盖 HTTP(S) 与 localhost 网址、去重及非法输入、配置持久化、书签解析、损坏文件保护、区域上限、位置交换、移除撤销、共享草稿、启动快照、重复点击、部分失败与重试、取消和迟到回调、保存失败恢复。VS Code 启动适配层另用临时测试程序验证参数中的空格和特殊字符、失败退出、超时和取消；不启动真实编辑器。

2026-10-24 验证：229 项原生测试通过，最终应用包构建成功。当前桌面窗口检查未通过，界面工具读取窗口超时，真实文件夹选择、编辑器与浏览器批量打开、三维选中及主窗口／沉浸模式交接仍待界面补验。

后续可增加资料文件夹、专注计时预设及更多编辑器。Chrome 当前标签和 VS Code 当前项目的实时同步需要独立扩展集成，当前版本只打开用户保存的入口。项目区域与 macOS Mission Control 桌面无关联。

## 第三批：AI 生成环境

先让文本模型生成声明式场景布局：主题、建筑模板、位置、颜色和装饰。不让模型直接生成可执行脚本。一个例子是「把开发区做成日式空中庭院，编辑器是主楼，文档在旁边，专注计时放在水池边」。

生成流程：文字描述 → 有版本的场景草案 → 本地校验 → 预览 → 用户应用 → 可撤销。布局草案仅引用现有入口 ID，不能改写本地应用／文件／网址绑定。工作文件内容、完整文件清单或浏览器标签不作为默认模型输入。

之后再支持真正的模型资产：用户导入 USD/USDZ 或选择三维生成服务。模型生成与普通文本助手是不同能力，现有 DeepSeek 文本接口不能直接当作三维模型生成器。服务选择、计费额度、输出授权、资产格式与失败重试均需单独设计。

加载模型前校验文件大小、包内引用、材质与几何复杂度；采用异步加载和占位模型。资产保存在应用工作区，不在每次启动时重新生成。任何生成失败都不覆盖最后一次可用环境。

验收：同一草案可确定性重放；未知模板、过量节点、非法数值或外部引用会被拒绝；取消与迟到的生成结果不会覆盖新场景；撤销可以恢复布局且不丢失应用绑定。

## 推荐实施顺序

先交付本地应用大楼和点击激活，再增加项目区域，最后接入 AI 主题与布局生成。只有用户确实需要独特建筑时再接三维资产生成。性能与打开工作上下文的效率优先于漫游效果。

## 原生能力参考

- [NSWorkspace.runningApplications](https://developer.apple.com/documentation/appkit/nsworkspace/runningapplications)：应用列表与变化观察。
- [NSWorkspace.openApplication](https://developer.apple.com/documentation/appkit/nsworkspace/openapplication(at:configuration:completionhandler:))：启动应用并处理结果。
- [VS Code 命令行](https://code.visualstudio.com/docs/configure/command-line)：使用 `--new-window` 打开项目目录。
- [Foundation 文件书签](https://developer.apple.com/documentation/foundation/nsurl/bookmarkdata(options:includingresourcevaluesforkeys:relativeto:))：保存和恢复用户选择的文件夹。
- [RealityKit Entity(contentsOf:withName:)](https://developer.apple.com/documentation/realitykit/entity/init(contentsof:withname:))：异步加载 USD/USDZ 与 Reality 资产。
