# Augma macOS

## Craft Hub 常驻入口

下一阶段采用[按需共享运行时](../../docs/plans/craft-hub-shared-runtime.md)，让 Electron 完全退出后仍可使用同一插件与登录直接记录到云端。该方案已确定职责与生命周期，但后台执行及小米云创建尚未实现；下面描述当前可用的摘要/草稿版本。

Craft Hub 主界面继续使用 Electron。Augma 复用现有菜单栏和快速记录草稿，增加今日重点缓存及唤起主界面的入口，不再启动第二套 Craft Hub 后端或读写其资料目录。

在 Craft Hub 的应用菜单选择「共享今日重点摘要…」并保存 JSON，再在 Augma 菜单栏或快速记录浮窗的 Craft Hub 区域选择该文件。摘要最多展示五项标题、来源、更新时间和读取覆盖范围；它始终标为缓存。Electron 退出后仍可查看摘要和输入记录；用 Craft Hub 应用菜单的「刷新共享摘要」更新文件，再在 Augma 重新读取。普通首页刷新不保证更新此文件。现有 Agent 项目只读授权保持独立，未扩大到工作项和账号。

「打开主界面」定位 Electron 应用；发行版或隔离验收副本可用「选择主应用…」指定，旧原生候选不会作为主界面打开。选择应用时默认定位「应用程序」目录；应用与摘要选择器均异步呈现，避免同步模态等待阻塞菜单栏面板，重复点击会前置已有选择窗口。取消保留原连接。摘要文件不含可执行路径或命令。停止共享会保留最后的摘要文件；Augma 中「断开」清除连接和内存缓存，不删除用户导出的文件。

「更多 → 快速记录浮窗」及「日常 → 快速记录」打开小型原生浮窗，与菜单栏编辑同一份草稿，复用既有的保存、发送和未知回执处理。关窗保留输入，退出 Augma 前刷新本机保存；重启自动恢复。原生 Craft Hub 候选的旧草稿不会被自动搬移或覆盖。本仓库当前最低系统为 macOS 26，本次未宣称兼容 macOS 15。

macOS 主窗口默认使用 Augma 布局：左上语音入口、右上系统按钮和底部圆形 Dock，中间展示原生应用内容。工具栏的布局按钮或 `⌥⌘0` 可切换为 SwiftUI 侧栏布局；选择会保存，主窗口之间共享布局偏好。两种布局共用窗口级 Store，切换不会清空笔记、网页、语音输入或空间状态。首次使用进入 3D「应用街区」，之后默认恢复上次活动窗口的页面和 3D 场景。日常功能包含快速记录、专注计时和快捷指令；系统监控、真实天气、当前播放信息与场景设置也独立在原生端运行。空间、摄像头、导航、通知、语音指令和设备面板中的按钮、开关、滑块、选择器、输入框与确认对话框均为原生控件。窗口跟随 macOS 的浅色 / 深色外观与辅助功能设置；最低支持 macOS 26，由系统提供 Liquid Glass 工具栏，辅助 HUD 的浮动按钮也使用系统玻璃样式。Augma 布局的顶部控制区和底部 Dock 使用原生安全区栏，滚动内容通过系统柔和边缘效果过渡。Augma 环形标识保留在品牌区和空间内容中。

顶部 AUGMA 时钟默认隐藏，可在「外观与语言 → HUD → 显示顶部时钟」或右上系统菜单独立开启，主窗口和沉浸模式共用并保存选择。菜单栏收纳继续通过「菜单栏 → 启用菜单栏收纳」按需开启。沉浸模式关闭时钟时，宽屏上的收纳栏上移到顶部控制行；开启时钟或屏幕较窄时，收纳栏自动放到下一行，内容区域同步避让。

在「Augma → 设置 → 窗口与快捷键 → 首页与启动」中，可选择恢复上次位置或指定首页；首页可设为任意模块，空间还可指定应用街区、项目区域、空中庭院或城市漫游，也可一键使用当前页面。偏好对之后新开的窗口生效，各窗口保留自己的当前页面；只有最后活动窗口更新下次启动位置。工具栏的首页按钮或 App 内 `⇧⌘H` 可返回指定首页，快速记录按钮或 `⇧⌘N` 可随时打开记录；App 内 `⌥⌘T`、工具栏的 To Do 图标及菜单栏「更多 → 打开 Microsoft To Do」均优先唤起本机 Microsoft To Do，未安装或启动失败时回退到系统浏览器。

空间采用「RealityKit 场景预览 + 原生控制面板」布局，庭院、城市、虚拟地标、模拟扫描、锚点和模拟路线均在原生端运行。「导航」使用 MapKit，「摄像头」使用 AVFoundation，「声音」展示本机网易云音乐的当前播放信息并支持播放、暂停和切歌。通知、语音助手和设备面板也直接使用 Swift 状态。内置应用功能使用原生界面，不包含隐藏 WebView、网页状态桥或打包的 AR 站点；用户主动打开的「网页」和 Augma Link 网页插件分别使用独立 WebKit 会话。

`NativeDemoModel` 持有窗口级的空间、通知、设备、助手与浏览会话，主窗口和沉浸模式注入同一组 Store。扫描与音频进度由小视图直接订阅。浏览器版本的 AR 演示继续独立维护，macOS 构建不依赖它。

按 `⌘1`–`⌘9` 或使用菜单栏的「应用」菜单可切换应用。主窗口使用原生菜单快捷键；语音保留 `⌥⌘V`。视界设置中的主题仅改变场景，原生窗口跟随系统外观。主窗口与其沉浸模式共享同一窗口级空间 Store，保留场景、扫描、锚点、模拟路线和视角；各自的 RealityKit 渲染视图从同一状态恢复。所有窗口与菜单栏共用原生设置、音频、地图和摄像头服务，不同主窗口的场景选择、镜头与模拟空间状态各自独立，应用街区的建筑和布局在应用级共享。

点击 Augma 布局右上角或侧栏布局工具栏的「沉浸模式」，界面会以透明悬浮层覆盖当前显示器的可用桌面区域。原窗口暂时隐藏，退出后恢复。空白区域默认允许点击穿透，应用面板和按钮仍可操作；左上角保留语音助手入口，顶部中央显示时钟，右上角提供通知、设置、系统菜单和退出按钮。底部原生圆形 Dock 可切换天气、声音、空间、摄像头、导航、网页、扩展中心与应用列表，也保留镜像、HUD、GitHub 与文档入口。右上系统菜单包含全部模块及「操作桌面」／「操作界面」切换；操作桌面时角落按钮和 Dock 仍可点击。可按 `⌃⇥` 在内容、Dock、语音入口和右上控制区之间切换键盘焦点。内容区域为顶部按钮和底部 Dock 留出空间，网页不会遮挡它们。菜单栏中的 Augma 菜单也提供这些操作。应用面板使用失焦后仍保持模糊的原生材质；Dock 和角落按钮使用 Liquid Glass，失焦后同样保持模糊。

Augma 运行时，默认全局快捷键 `⌃⌥A` 可从任何应用唤起／隐藏沉浸助手。首次唤起使用最近活动的主窗口；主窗口已关闭时会创建一个。隐藏时主窗口不会弹出，当前内容与浏览会话仍保留，空间与摄像头视图会卸载、语音识别停止、网页媒体暂停；再次唤起恢复同一状态。`Esc` 或右上退出按钮则结束沉浸模式并恢复主窗口。在「Augma → 设置 → 窗口与快捷键」中可选择 `⌃⌥⌘Space` 或关闭全局快捷键；注册冲突会显示错误并允许重试。该快捷键使用系统热键注册，不依赖键盘监听或辅助功能授权。菜单栏的「沉浸助手」和状态栏「更多」也提供唤起／隐藏入口。

每次启动 App 后首次展示沉浸助手时播放约 700 ms 的横线与涟漪动画；后续唤起统一使用 140 ms 淡入，隐藏使用 100 ms 淡出，画布、Dock 和角落控件同步过渡。退出沉浸模式再进入也不会重播启动动画。快速连续切换时，旧淡出的回调不会卸载新显示的内容或抢回焦点。启用系统「减少动态效果」时跳过启动动画和淡入淡出，直接显示／隐藏。


需要 macOS 26 或更高版本、Xcode 26 或更高版本、Node.js 24 和 pnpm。最低部署版本为 macOS 26.0，优先在 macOS 26 与 27 上验证。在仓库根目录运行 `pnpm mac:run` 可打包并启动；运行 `pnpm mac:verify` 可额外检查进程和演示窗口。两条命令都调用 `script/build_and_run.sh`，默认只构建 arm64；Intel Mac 开发者可用 `AUGMA_BUILD_ARCH=x86_64` 覆盖。脚本直接构建 SwiftPM 可执行文件并打包为 `apps/mac/dist/Augma.app`，不运行 Vite 或打包 AR 网页资源。Node.js 仅用于版本号和图标清单校验；也可直接运行 `./script/build_and_run.sh --verify`。原生功能离线可打开；地图、天气、网页和在线助手按需联网。运行 `pnpm mac:package` 则分别构建 arm64 与 x86_64 的 Release 版本，进行 ad-hoc 签名并压缩为 `apps/mac/dist/Augma-macOS-arm64.zip` 和 `Augma-macOS-x86_64.zip`（各附 `.sha256`），版本号取自根目录 `package.json`。`pnpm mac:package arm64` 或 `pnpm mac:package x86_64` 可只生成一种架构。主程序与 NowPlaying 动态库均验证为对应的单架构；发布 App 在临时目录组装，不覆盖本机 App。两种包全部完成后移除旧的通用 ZIP。

本地运行、调试和验收构建使用稳定证书签名。首次运行时自动选择唯一的有效 Apple Development / Mac Developer 证书，将其 SHA-1 固定到 `apps/mac/.signing-identity.local`（已被 Git 忽略），后续重编复用该证书。若有多个开发证书或使用自签名 Code Signing 证书，先运行 `security find-identity -v -p codesigning`，再用 `AUGMA_CODESIGN_IDENTITY='<证书 SHA-1 或完整名称>' pnpm mac:run` 显式选择；成功后会保存选择。没有证书时可在 Xcode 添加 Apple Development 身份，或在「钥匙串访问」创建自签名 Code Signing 证书。固定证书缺失、过期或签名失败时构建报错，不会自动切换身份或退回 ad-hoc。证书及私钥保留在本机钥匙串，不导出到仓库。

从旧的 ad-hoc 构建首次切换到证书签名时，首次主动使用 To Do 可能仍需授权一次；选择「始终允许」后，相同证书与应用标识的后续开发构建可沿用该授权。发布包仍使用原来的打包流程，不复用本机开发签名。

App 图标是深蓝底板上的白色字母 A，外围是与原生 `AugmaRing` 同款的环形 HUD：青色细环和两段相对的圆头橙色弧。原稿归档在 [YunLeFun/icons](https://github.com/YunLeFun/icons/tree/main/assets/apps/augma/v1)（`ylf:augma-app-icon` / `ylf:augma-mark`），`assets/brand` 保存固定版本的副本与同一份 SHA-256 清单：`pnpm icons:check` 校验本地副本，`pnpm icons:sync --source /path/to/YunLeFun/icons` 从中心原稿更新。打包脚本先校验清单，再用 Xcode 26 及以上的 `actool` 把分层的 `Augma.icon` 编译为 `Assets.car`，供 macOS 26 的默认、深色、Clear 与着色外观使用；`AppIcon.icns` 由 `augma-app-icon.svg` 按 Apple 1024 px 模板渲染，作为常规图标资源的兜底。

菜单栏右侧的 Augma 图标使用原生 `MenuBarExtra` 下拉面板，可直接输入并保存记录、查看倒计时、暂停 / 继续 / 延长 / 结束计时，以及打开快捷指令和语音输入。图标保持静态，秒级更新只发生在计时读数中，避免状态栏图标反复栅格化。菜单中的「更多」保留演示应用、播放控制、窗口置顶、设置、辅助 HUD 和鼠标穿透入口。操作优先定位最近使用的主窗口并恢复最小化窗口；主窗口关闭后会重新打开到所选面板。HUD 浮窗在 macOS 26 上使用 Liquid Glass，RealityKit 场景只在用户主动进入演示空间时创建。

「设置 → 菜单栏」提供默认关闭的「菜单栏收纳」。开启后，从 Augma 菜单栏面板、「窗口 → 菜单栏收纳」或全局快捷键 `⌃⌥B` 展开刘海下方的横向图标条。点击图标会先收起收纳栏，再直接触发原应用的菜单栏按钮，由原应用展示自己的菜单或自定义面板（如 Magpie）。菜单中的图标、自定义视图、动态内容及交互均由原应用保留，Augma 不再读取文本重建菜单。系统图标和鼠标位置保持不变。图标右键菜单可请求原应用的「显示菜单」动作。`Esc` 或点击外部关闭收纳栏，关闭功能会注销快捷键并停止扫描与截图。

用快捷键呼出全屏 Augma 时，已启用的收纳栏跟随界面出现在当前屏幕顶部居中、时钟下方。全屏模式使用紧凑图标条，悬停查看名称，超出宽度时横向滚动，内容面板自动向下让位；点击其他 Augma 控件不会关闭图标条。在外接屏呼出时也展示内建刘海屏被遮挡的图标。原菜单的弹出位置由原应用和系统决定，不能保证跟随 Augma 中的图标；菜单关闭后恢复全屏中的收纳栏。收起或退出全屏 Augma 会一起隐藏收纳栏，停止刷新。

收纳操作需要辅助功能权限，仅在用户点击授权按钮后请求。默认使用应用图标；多显示器下若无法确认图标归属，会引导允许屏幕录制以读取图标窗口信息，不向未知控件发送操作。可选的「显示原始状态图标」同样需要屏幕录制权限，只截取图标窗口、只在收纳栏打开时刷新，截图不写入磁盘。旧版图标位置恢复记录在升级为直接菜单操作后停用，不再阻挡菜单打开。

系统交互集中在 `MenuBarShelf` 模块。macOS 26 的图标由控制中心绘制，识别结合 `AXExtrasMenuBar` 和窗口几何，并关联多显示器上的窗口副本。菜单使用 `AXPress` / `AXShowMenu` 直接打开，打开前校验原进程和状态栏控件身份，并等待实际菜单窗口出现和关闭；不使用 WindowServer 拖动兼容层。`swift test --package-path apps/mac --filter MenuBarShelfTests` 验证点击图标直达原菜单、过期图标身份、错误与取消清理；`./script/verify-menu-bar-shelf.sh` 提供独立测试应用的原生菜单验收入口。

各应用对菜单辅助功能的支持不同；未暴露可用状态栏按钮动作、控件已失效或实际没有弹出菜单时，会明确提示失败，不会回退到文本重建菜单或执行子菜单中的任意命令。

主窗口工具栏和菜单栏都提供「始终置顶」开关；开启后演示窗口会显示在其他普通窗口上方，设置会在下次启动时保留。辅助 HUD 使用普通窗口层级，仅在所属桌面显示，不受主窗口置顶开关影响；沉浸模式仍使用悬浮层。

桌面版摄像头使用系统 AVFoundation 权限，不通过 WebKit；原生相机预览不提供 ARKit 世界追踪或真实环境扫描。空间使用 RealityKit 的非 AR 渲染，不申请摄像头权限；已移除空间透明 WebView 及其非公开背景设置兼容。WebXR 仅保留在普通浏览器演示中，内置网页浏览器不继承原生摄像头或语音权限，也不接入原生动作桥。推送 `v*` 标签时，发布工作流会把同一个压缩包附加到该版本的 GitHub Release，站点的[下载页](https://augma.yyj.moe/guide/macos)指向最新版本。安装包尚未使用 Developer ID 签名和公证，首次打开需在「系统设置 → 隐私与安全性」中点击「仍要打开」。

在「设置 → 菜单栏 → 菜单显示内容」可分别显示或隐藏快捷指令、语音输入、快速记录、专注计时、Craft Hub 今日重点与系统监控。修改立即生效并在重启后保留，面板随内容缩短。隐藏快速记录保留已有草稿，各功能仍可通过主窗口、快捷键或「更多」菜单打开。

## 日常功能

- **快速记录**：统一输入入口，选择「笔记 → 备忘录」或「待办 → To Do」。笔记通过 macOS 自动化写入备忘录默认账户的默认文件夹；待办通过 Microsoft Graph 写入所选清单。主窗口和菜单栏共用草稿、目标偏好与发送状态。选择「待办 → To Do」后，可在输入框上方直接选择清单、刷新清单或打开本机 To Do；尚未恢复连接时，可直接点击「连接 Microsoft To Do」使用已有凭据或登录。窄面板自动分行，所选清单会保存到下次使用。先将内容保存到本地再发送，收到成功响应后移出本地列表；失败保留内容，可编辑、重试、复制和导出 Markdown。无法确认发送结果时要求先检查目标应用再重试，以免重复创建。旧版本的本地记录保留，可逐条转存，不会自动上传。每条记录上限 20,000 字符。
- **专注计时**：25 分钟专注 / 5 分钟休息快捷入口，自定义分钟数，暂停、继续、延长 5 分钟、结束和完成历史。可打开始终置顶的紧凑计时窗。关闭主窗口不会退出应用，计时服务仍继续；退出 App 后保留截止时间，重新启动时恢复或补记完成。睡眠与系统时间调整后按绝对截止时间校准，不通过累加 UI 刷新次数计时。

### 连接备忘录与 Microsoft To Do

在快速记录的「连接设置」或 App 设置的「快速记录」页配置。备忘录首次发送会请求「自动化」权限；拒绝后可在「系统设置 → 隐私与安全性 → 自动化」允许 Augma 控制备忘录。请先在备忘录中配置默认账户；选择 iCloud 账户时，设备间同步由备忘录负责。内容以转义后的 HTML 写入，原始记录不作为脚本代码执行。

Microsoft To Do 使用系统浏览器登录会话、OAuth 授权码 + PKCE 和 `state` 校验，只请求 `Tasks.ReadWrite` 与 `offline_access`，不需要 Client Secret。刷新凭据保存在 macOS 钥匙串，访问令牌只留在内存；工作区 JSON 和 UserDefaults 不保存令牌。发送时绑定账户连接标识及清单 ID，换账户或清单失效后需要主动选择「改用当前目标重试」。

启动、显示页面和保存应用 ID 都不会读取 Microsoft 钥匙串凭据。点击「连接 Microsoft To Do」或主动发送待办时才读取；已有凭据优先恢复，没有凭据时连接按钮才打开 Microsoft 登录。授权失败时保留待发送内容，等待用户主动重试；成功读取后在当前进程内复用，不因页面刷新重复请求授权。重启后连接状态在首次主动使用时确认，保存的目标清单和待发送条目的账户绑定继续保留。

仓库的 `Config/microsoft-todo.json` 保存 Augma 的公开 Client ID，本机运行和 GitHub 发布构建都会自动内置它。使用包含该配置的新版安装包时，用户只需点击「连接 Microsoft To Do」、完成授权并选择清单，无需注册应用或填写 Client ID。每位用户的登录凭据独立保存在各自 Mac 的钥匙串中。组织账户仍受所在租户的[用户同意和发布者验证策略](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/configure-user-consent)限制，必要时需管理员批准。

维护者可自动创建或校验应用配置。先安装 [Azure CLI](https://learn.microsoft.com/cli/azure/install-azure-cli)，使用有应用注册权限的账号登录目标目录，再运行：

```sh
az login --allow-no-subscriptions --tenant <你的租户 ID>
pnpm mac:setup-todo
pnpm mac:check-todo
```

脚本复用配置中或当前用户拥有的唯一同名 Augma 应用；没有时创建支持个人及组织账户的原生公共客户端，设置回调和 `Tasks.ReadWrite` / `offline_access` 委托权限。已有应用必须通过账户类型、原生回调和任务权限检查，配置不兼容时停止并提示；不会修改其他应用或授予租户级管理员同意。多个同名应用需要明确指定 `pnpm mac:setup-todo --client-id <应用 UUID>`。已在门户配置好的应用，也可在「清单 → Microsoft Graph 应用清单（新）→ 下载」后运行 `pnpm mac:setup-todo --manifest '/path/to/Augma.json'`，无需安装 Azure CLI。

脚本只将公开 Client ID 写入共享配置；提交此配置后，其他开发者和发布流程可直接复用。访问令牌、刷新令牌、Client Secret 和 Azure CLI 会话均不会写入仓库。发布工作流及 `pnpm mac:package` 在构建前校验 Client ID，缺失或格式无效时停止，避免生成无法登录的发布包。`AUGMA_MICROSOFT_CLIENT_ID` 环境变量可覆盖共享 ID；GitHub Actions 支持同名 repository variable，空值自动使用仓库配置。本机开发构建允许尚未配置时使用备忘录。

Fork 或自建应用也可手动注册：

1. 打开 [Microsoft Entra 应用注册](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade)，登录有应用注册权限的账号，并确认右上角所选目录。点击「新注册」。如果账号没有可用目录或注册权限，需要先由该目录管理员提供访问权限。
2. 名称填写 `Augma`；受支持的账户类型选择「任何 Entra ID 租户 + 个人 Microsoft 账户」（旧版界面为「任何组织目录中的账户和个人 Microsoft 账户」），以支持个人 To Do 和组织账号。
3. 在同一表单的「重定向 URI」中选择 **公共客户端/本机（移动和桌面）**，填写 `msauth.cn.yunyoujun.augma.desktop-demo://auth`。查看页面链接的 Microsoft 平台策略后点击「注册」。也可以先留空，在注册后的「身份验证 → 添加平台 / 添加重定向 URI → iOS / macOS」中填写 Bundle ID `cn.yunyoujun.augma.desktop-demo`，生成同一回调地址。
4. 注册完成后，在「概述」复制 **应用程序（客户端）ID / Application (client) ID**。这是形如 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` 的公开 UUID；不要复制对象 ID 或目录（租户）ID，也不需要创建客户端密码 / Client Secret。
5. 打开「API 权限 → 添加权限 → Microsoft Graph → 委托的权限」，搜索并勾选 **Tasks.ReadWrite**，点击「添加权限」。这项权限允许应用读写当前登录用户的任务和清单；不要选择 `Tasks.ReadWrite.All` 应用程序权限。`offline_access` 由 Augma 登录时请求，用于保持连接。组织账户是否允许用户同意取决于管理员策略。
6. 要让自己的构建供多人使用，运行上面的配置脚本保存共享 ID。仅覆盖本机时，在 Augma 中打开「快速记录 → 连接设置 → 自定义 Microsoft 应用（高级）」，粘贴 Client ID，点击「保存应用 ID」。也可以从「Augma → 设置 → 快速记录」进入。该覆盖配置保存于本机，无需重新构建；断开连接后可点击「使用 Augma 默认配置」恢复共享应用。
7. 点击「连接 Microsoft To Do」，使用实际管理 To Do 的账号登录并确认授权。返回 Augma 后，等待清单加载，选择「待办清单」。快速记录切换为「待办 → To Do」后即可发送；没有 Client ID 的构建仍可使用备忘录，待办内容会保留在本地等待配置后重试。

打包脚本将所选公开 Client ID 写入 Info.plist 并注册回调 scheme；本机已保存的有效 Client ID 优先于构建配置，旧的空值或无效值会回退到内置配置。登录出现重定向地址不匹配时，核对门户中的地址是否与上述 URI 完全一致，并确认平台类型为原生公共客户端。

## 原生设置、音频与共享场景

主窗口「设置」、App 设置窗口的「外观与语言」页和沉浸面板使用同一个 `NativePreferencesStore`。场景外观、HUD、应用语言与语音反馈保存在原生 UserDefaults；没有 WebView 也能修改。已有原生保存值和之前迁移的值继续保留；新版本不再读取旧 WebView 的 localStorage。恢复场景默认仅恢复场景偏好，不清除笔记、助手密钥或监控设置。原生控件外观仍跟随 macOS，应用语言可单独选择。

「声音」显示本机网易云音乐的歌名、歌手、专辑、封面、播放状态与可用的进度。歌曲信息旁提供「上一曲／播放或暂停／下一曲」按钮，中间的播放按钮更突出；声音面板打开时可按 `⌥⌘←`、`⌥⌘P`、`⌥⌘→` 操作。主窗口和沉浸模式共用 `NativeAudioStore`，请求期间禁用重复点击；播放／暂停等待播放器回报新状态，切歌等待播放器确认命令，歌曲信息和歌词由后续播放样本更新。上一曲可能按网易云行为重播当前歌曲。控制失败或确认超时会显示可重试提示。观察、打开面板、休眠与退出不会自动改变播放。播放位置使用系统原生 `Slider`，拖动时预览时间，松手后提交一次跳转；键盘及辅助功能调整会合并连续操作。等待播放器实际位置确认后结束请求，失败则恢复真实位置并显示提示。仅对报告可跳转且拥有有效时长的网易云会话启用拖动，其他情况保留只读进度；换歌、来源变化、休眠或退出会取消未完成操作。调音量、收藏和播放列表编辑仍在网易云完成，不包含内置合成音。语音和快捷指令支持「查看正在播放」。网易云未运行、没有当前播放信息、读取失败和缺失封面均有独立状态；切换来源或退出网易云会清空旧歌曲，休眠停止读取并取消待处理控制，唤醒后恢复观察。

播放控制旁的列表按钮可切换歌词与「当前播放队列」，展示歌曲、歌手、时长和数量，支持定位当前曲。标题和底部说明通过 `safeAreaBar` 接入 macOS 26 原生 `.scrollEdgeEffectStyle(.soft)`，滚动内容在上下边缘柔和淡出，首末歌曲完整保留。队列按本机 `playingList` 的显示顺序读取，只有面板可见时每三秒更新一次；多窗口共享读取，关闭最后一个队列面板、失去网易云会话、休眠和退出时停止。当前曲按歌名、已署名歌手、专辑和时长严格匹配；同名错版、重复位置或无法唯一匹配时不猜测高亮。队列为空有单独提示；文件缺失、格式错误和超出 16 MiB 会显示可重试的读取失败，不改写网易云文件。来源标识使用本机已安装网易云的应用图标，保留名称文字，缺少图标时回退为音符。

2026-11-05 在网易云音乐 3.1.13 上验证了原生「控制 → 喜欢歌曲／取消喜欢」菜单：切换后菜单状态改变，并已恢复原收藏状态；快捷键设置显示应用内 `⌘L`、全局 `⌥⌘L`。后续可通过原生菜单自动化接入，但需要为 Augma 单独处理辅助功能授权，当前没有加入收藏按钮。原生队列双击点播已验证，列表内容没有暴露可按歌曲定位的辅助功能节点，不能把坐标点击当成稳定的 App 接口。`orpheus` 歌曲深链接试播被浏览器安全策略拒绝（仅允许 HTTP(S)），因此该入口仍未验证；本次队列只读，不提供点播或收藏入口。

媒体桥接位于 `Support/NowPlaying`，由构建脚本编译并打包。它使用系统 `/usr/bin/perl` 加载 MediaRemote 桥接，每两秒读取一次本机媒体会话，仅接受 `com.netease.163music` 来源，数据只保留在内存。控制由独立的短时进程发送白名单中的播放、暂停、上一曲、下一曲或指定时间跳转命令，发送前再次核对当前来源并指定网易云标识，跳转前还会校验歌曲信息生成的稳定标识、可跳转能力及目标范围，不模拟全局媒体键，也不自动启动播放器。网易云会在暂停与跳转时重建媒体条目 UUID，因此不把该 UUID 当作歌曲标识；元数据完全相同的重复条目按同一首歌曲处理。接口签名参考 [WebKit MediaRemoteSPI](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/PAL/pal/spi/mac/MediaRemoteSPI.h)，系统宿主方案参考 [mediaremote-adapter](https://github.com/ungive/mediaremote-adapter)。MediaRemote 是私有系统接口，macOS 或网易云升级后可能需要适配；当前方案用于本机桌面版本，不承诺 Mac App Store 兼容。桥接不含网络调用，不读取网易云账号、Cookie、缓存库或收听历史。

歌词优先使用本机播放元数据；缺失时，只读网易云的 `playingList`，按歌名、已署名歌手、专辑和时长（允许 2 秒误差）匹配唯一歌曲 ID，然后联网请求网易云 LRC 与译文。系统媒体会话可能只报告一位已署名歌手，本地队列的完整演唱者名单用于核对，不做歌手名称的子串匹配。没有唯一 ID、网易云请求失败或未返回歌词时，使用 LRCLIB 的歌曲签名查询，并再次验证歌名、歌手、专辑和时长，拒绝错版结果。网易云 Web 歌词接口和本地队列格式均非稳定公开契约；两种来源都不可用时保留可恢复状态。相关接口参考：[网易云开源实现](https://github.com/feeluown/feeluown-netease/blob/master/fuo_netease/api.py)、[LRCLIB 文档](https://lrclib.net/docs)。

歌词请求不使用网易云登录态、Cookie 或账号信息；网易云请求只发送歌曲 ID，LRCLIB 查询发送歌曲名称、歌手、专辑和时长。没有 OCR，也不需要辅助功能或屏幕录制权限。请求仅在切歌或主动重试时触发；播放进度样本不重复联网。切歌、休眠、失去当前播放信息或退出 App 会取消当前请求，迟到响应不能覆盖新歌曲。

带时间戳的歌词按本机播放进度滚动并高亮当前行，切行时平滑滚动、淡化高亮，固定字重避免文字换行抖动；启用系统「减少动态效果」时直接切换。歌词视口上下使用透明渐变，首尾保留阅读空间，同步歌词和纯文本歌词均隐藏滚动条，仍可手动滚动。支持暂停、恢复、进度跳转、LRC 偏移、多时间戳、重复时间与同步译文；歌词行没有点击跳转或播放控制。纯文本歌词只显示文字，纯音乐、未匹配和网络错误各有状态。界面标明歌词来源和本地缓存。已获取歌词保存于 `~/Library/Caches/<App Bundle ID>/Lyrics/v1`，文件名为歌曲签名的 SHA-256，最多保留最近使用的 256 个条目；缓存可在断网及重启后读取。缓存损坏或写入失败不影响播放信息，也不会写入播放器的数据目录。浏览器 AR 演示的 Web Audio 行为独立于 macOS 应用。

进入沉浸模式时，空间由新的 RealityKit 视图呈现同一个 `NativeSpaceStore`；扫描和模拟路线不会因视图重建而重新开始。通知列表、设备状态、助手输入与回复和当前网页同样保留。网页将当前标签页的 WKWebView 重新挂载到悬浮层，保留历史、滚动位置与页面状态；背景标签页继续保留各自的页面。Dock 和角落按钮可切换模块、语音、HUD、桌面穿透或退出；按 Escape 或右上角退出按钮回到主窗口。不同主窗口的空间、通知、设备、助手和网页会话各自独立；偏好、音频、地图、摄像头、记录、计时、监控与天气由 App 共享。

## 通知、设备与沉浸式网页

「通知」记录当前窗口会话的应用活动，包括模拟扫描完成、场景切换、固定锚点、路线到达和模拟设备连接变化。最多保留 100 条，仅在内存中保存，支持标记已读和清空；不读取 macOS 通知中心历史。专注计时的系统本地通知继续由独立的原生服务处理。

「设备」保留连接、待机、断开与约 0.9 秒的模拟重连，明确标注为设备模拟；显示当前 RealityKit 场景、地标、扫描、锚点、模拟路线和实际原生摄像头状态。待机或断开会取消本窗口的扫描、路线和助手任务，其他原生功能仍可使用，不影响全局音频播放。

「网页」提供原生标签栏、地址栏、前进 / 后退、刷新 / 停止、加载错误，以及外链快捷图标。点击标签栏的 `+` 或按 `⌘T` 新建标签页，`⇧⌘[` / `⇧⌘]` 切换标签页，也可点击标签页名称或关闭按钮。输入 HTTP(S) 网址，或输入关键词使用 Bing 搜索。标签页在首次导航时才创建 WebKit，切换标签页不会重新载入背景页面；主窗口和沉浸模式共享同一组标签页、页面状态及浏览历史。点击外链图标可直接使用系统默认浏览器打开当前页；点击旁边的下拉箭头可选择 Safari 或已安装的 Google Chrome，未安装的浏览器选项会禁用。沉浸模式将网页扩展到桌面可用区域，顶部保留 Augma 角落按钮，并按偏好显示时钟和菜单栏收纳，底部保留 Dock；Escape 退出沉浸模式。新窗口链接打开到新标签页；下载交给默认浏览器。

网页使用 WebKit 默认网站数据存储，Cookie 与登录状态遵循 WebKit 的持久化行为；关闭标签页释放对应页面，关闭主窗口结束该窗口的全部浏览会话，不清除网站数据。网页不注入 Augma 状态、脚本消息处理器或本地资源协议，摄像头与麦克风访问当前不开放。

## 原生模拟空间

「空间」使用 RealityKit 的非 AR `ARView`，通过小型 AppKit 桥接提供明确的透视相机和鼠标交互。空中庭院采用低多边形与赛璐璐色块风格：前景保留观景平台、玻璃回廊、中央树和步道，远处是七层收拢的白色浮空城、尖塔与切面悬岩，少量浮岛和云层形成纵深。`NativeFloatingGarden.swift` 按材质合并程序生成的切面网格，无需贴图或外部模型。城市场景包含美术馆、玻璃车站、公共广场、道路和错落楼群。点击模型或编号标记可选择地标，也可通过原生列表操作；当前选择显示青色标记，固定锚点显示金色标记。

「扫描空间」是约 2 秒的模拟扫描，使用单调时钟计算 0–100% 进度，渲染扫描环、扫线与进度刻度。完成后可为所选虚拟地标固定或取消锚点；选择其他地标不会把原锚点移过去。模拟路线有 4 次手动推进，显示演示距离、进度和场景中的路线标记；选择其他地标会结束当前模拟路线。切换庭院 / 城市会重置地标、扫描、锚点、路线和视角。这里不使用摄像头、空间传感器或地理位置，不识别真实环境；虚构地标不会传给苹果地图。

每个主窗口的 `NativeDemoModel` 持有一个 `NativeSpaceStore`，主窗口与其沉浸模式共用场景、选中地标、扫描进度、锚点、模拟路线和视角。主窗口和沉浸模式分别创建渲染视图，重建几何时从共享 Store 恢复状态。拖动旋转、滚动或触控板缩放会写回同一视角；原生按钮也提供缩放与复位。庭院默认从约 1.5 米的步行视点向远处眺望，拖动转动视线，缩放限制在庭院内短距离前后移动；扩展到镜头身后的草地和两侧植被形成前景包围，远城后移并使用较淡的冷色减弱反差。场景支持明暗、背景、镜像、专注和 HUD 偏好；指针视差仅在开启「景深动效」且系统未启用「减少动态效果」时响应鼠标移动。庭院云层缓移与小岛浮动使用 RealityKit 内置动画，系统减少动态效果、窗口非活动或遮挡、隐藏背景和专注模式均会暂停；切换场景或移除视图时停止并清理。扫描使用有限任务，结束、取消、休眠或关闭窗口时停止；渲染不创建常驻动画计时器。

## 原生地图导航与摄像头

「导航」使用 MapKit 原生地图。分别输入并搜索起点和终点，从结果中选择真实地点后，可查询驾车或步行路线，查看路线线条、距离、预计时间与分步指引；也可将同一组起终点和出行方式交给「苹果地图」。本版本不自动获取当前位置，不申请定位权限，也不提供行进中的自动偏航重算或语音领航。地图加载、地点搜索与路线查询使用 Apple 服务，具体路线与预计时间依地区和路况而变化。搜索、路线、地图视角和分步列表的展开状态仅保留在应用内存中，主窗口、其他窗口和沉浸模式共享；切换视图不会清空查询或重复请求。分步指引通过原生按钮展开或收起，步骤按实际显示顺序连续编号。请求有取消、过期结果隔离、限流及超时处理。

空间内的观景平台、玻璃回廊等是虚构地标，没有真实经纬度；它们的手动路线演示留在「空间」面板，并明确标注为模拟路线，不传给苹果地图。快捷指令与语音中的「打开地图」「打开导航」「打开摄像头」可直接打开原生面板，不创建 WebView，也不会自动开启摄像头。

「摄像头」使用 AVFoundation 与 AVCaptureVideoPreviewLayer。只有主动点击「开启摄像头」才请求系统摄像头权限并启动采集；支持可用的内置、外接及连续互通相机，具体设备取决于 macOS 和连接状态。镜像开关只影响预览，JPEG 照片保持原始方向。拍照后图片先保留在内存，点击「保存照片…」并选定位置后才写入本机；不请求麦克风、不录音、不上传画面。拒绝授权、设备缺失、断开、占用或保存失败均显示相应提示，可重试或进入系统隐私设置。

同一个原生摄像头会话在主窗口与沉浸模式之间共享。短暂的窗口交接保留采集；真正离开摄像头页面、窗口隐藏或最小化、应用失活、Mac 睡眠和退出时停止。回到应用不会自动重新开启。权限用途说明提供中英日三语；自动化测试使用注入的权限和采集后端，不会实际打开摄像头。

## Codex 占用与清理

在系统监控 → 清理磁盘与内存中选择「分析 Codex 占用」，按需统计已知桌面缓存与诊断日志。展开候选、手动勾选后可生成本地清理预览；默认不选中，预览前重新核对文件信息。逐项审阅预览后，可再次确认将所选文件移入废纸篓，不自动清空。执行前必须退出 Codex 桌面应用及 CLI；文件变化会跳过，结果逐项显示，并在下次打开时恢复最近一次回执。会话、历史数据库、工作树和生成成果不进入本次扫描。

无需安装 Mole 即可使用原生分析。可选 Mole 只复核一个完整扫描过的缓存/日志范围，结果单独显示，不增加候选、不与原生容量相加；未安装或版本不兼容时原生功能保持可用。执行合同见[清理执行记录](../../docs/plans/2026-11-05-codex-storage-execution.md)。统计口径、预算、排除范围和测试说明见[实施记录](../../docs/plans/2026-11-05-codex-storage-preview.md)。

## Augma Link · 扩展中心

在侧栏「系统 → Augma Link · 扩展中心」、底部 Dock 的拼图图标，或右键 Dock 选择「Augma Link · 扩展中心」。也可输入「打开 Augma Link」或「打开扩展中心」；原来的「打开应用市场」指令继续兼容此入口。

Augma Link 面向 Augma 自身的功能和扩展。「插件」可查询在线目录，下载并安装 **Breathing Orbit（呼吸环）**。宿主核对下载大小、SHA-256、资源路径与清单后安装，默认停用；启用后可打开或加入 Dock。离线时仍可点击「安装示例插件」或「从文件夹安装…」导入带有 `augma-plugin.json` 的文件夹。停用、卸载会关闭所有窗口中的对应页面，并移除 Dock 入口。状态在重启后恢复，插件只在打开时运行。示例使用独立 HTML / CSS / JavaScript，位于当前 monorepo 的 `plugins/breathing-orbit`，作为独立版本的 pnpm workspace 包。格式、分发协议与联调方法见[插件开发说明](../../docs/plugins.md)。

「内置功能」可搜索原生功能、筛选已加入 Dock 的入口，直接打开、加入或从 Dock 移除。快速记录、专注计时、系统监控等功能均可固定，排序在主窗口与沉浸模式共享并在重启后恢复。内置功能随 Augma 提供，无需额外安装。插件自动更新、作者签名认证和原生权限接口尚未接入。

「本地工具」保留 **Mole CLI** 与目标清理功能；清理指令会自动切换至此页。安装按钮通过已安装的 Homebrew 调用官方 `homebrew/core/mole` formula；先检查来源和正式版本，当前适配 **1.64.0**。命令行版免费开源，GPL-3.0-or-later；不需要购买另行提供的 Mole 桌面应用。已有 CLI 不会被自动升级，未知版本只显示受限状态。Augma 不内嵌或移植 Mole 源码。

## 应用列表

本机 macOS 应用入口与 Augma 扩展目录独立。在侧栏「系统 → 应用列表」、底部 Dock 的网格图标，或右键 Dock 的「浏览与添加应用…」中查看；也可输入「打开应用列表」。

「已安装应用」列出 `/Applications`、`~/Applications` 与系统应用目录中的有效 macOS 应用，支持按显示名称、应用文件名或 Bundle ID 搜索，直接打开或加入 **Augma Dock**。重复安装按 Bundle ID 合并，优先显示用户应用目录中的副本；不会展开应用包内的辅助程序。返回 Augma 或点击刷新会更新安装状态。

「App Store」输入名称并点击搜索，使用 [Apple Search API](https://performance-partners.apple.com/search-api) 查询系统地区对应的 Mac 应用商店，最多显示 50 项，包含图标、开发者和商店价格。只有提交查询时才发送关键词；点击「在 App Store 查看」进入系统 App Store，由系统完成购买、下载和安装。返回后刷新，按同一 Bundle ID 识别已安装应用并显示「加入 Dock」。网络失败可重新查询，查询期间更改关键词或切换页面会丢弃迟到结果。

## 按目标清理

可在 Augma Link 的「本地工具」、原生语音助手或快捷指令中输入「**帮我尽量腾出 20 GB，保留模型和最近项目。**」。本地解析容量目标并进入同一个清理 Store：调用 `mo analyze --json <目录>` 查看占用，再以原生白名单扫描器生成可执行候选。数字 GB/MB/TB 按十进制解释，也支持 GiB/MiB/TiB。笔记和待办捕获优先，记录中的清理文字不会触发操作。

模型目录与项目源码始终不在执行范围内；最近项目暂按保留**全部 Xcode 构建缓存**处理，避免仅凭缓存时间推断项目是否活跃。当前目标计划只允许把下载顶层至少 7 天未修改的 dmg/pkg/xip 移入废纸篓，并额外排除名称涉及模型的安装包。其他 Mole 占用行只能在 Finder 查看。界面显示候选估算、受保护候选数、容量缺口和不完整扫描，不承诺一定释放 20 GB。Mole 通用 `clean` 会扩大动作范围且可能清空废纸篓，因此没有接入为自动执行命令。

本地计划无需模型配置。「AI 优化计划」复用当前 AI 运行时（DSH 或 DeepSeek），确认后仅发送目标容量、保留规则、完整性和最多 12 项的匿名 ID、类别与大小；不发送原始指令、文件名、路径、报告或内容。AI 只能从这些候选中调整，不能生成命令或批准。计划默认不勾选，执行需核对具体文件并确认；确认绑定计划 ID、候选 ID、扫描目录和 5 分钟有效期，文件元数据变化时跳过。移入废纸篓不立即释放磁盘空间；回执显示移动/跳过数量及操作前后同卷可用容量，清空废纸篓由用户自行决定。

检测、安装、分析均为有超时与输出上限的一次性进程，安装最多 5 分钟，目录分析最多 45 秒，输出合计上限 4 MiB。分析失败或超时会显示原因并回退本地计划，可选择更小的扫描目录。离开最后一个本地工具视图会取消只读任务并丢弃迟到 AI 回复；安装和确认后的移动会完成并产生结果，期间退出应用会提示等待。没有后台扫描或轮询。清理引擎的 Purge 适配、原生第三方引擎插件、应用卸载管理和外部 MCP 尚未实现。

## 只读空间分析

系统监控 → **空间分析** → **选择目录…**，按需查看空间区块图、当前目录的前 20 项、大目录排行和本机生成的检查建议。点击目录区块下钻，使用「上一级」「扫描根目录」返回；文件和列表项可在 Finder 中定位。首版不提供删除、压缩、迁移或自动清理动作，不发送文件信息给 AI。原有专项清理面板保持独立。

可切换「磁盘分配」与「逻辑大小」。前者按文件的分配块统计，不含目录本身开销；后者按文件长度统计。硬链接只在首次遇到的目录计一次，父子目录排行不能相加。APFS 共享数据、快照、稀疏文件和云端占位文件都会影响这些数字与独占占用、可释放空间的关系；这里不估算清理收益，也不模拟系统设置的「文稿」分类。

仅读取所选根目录内的元数据，包含隐藏文件；不跟随符号链接、不跨卷、不打开文件内容或主动下载云端内容。扫描有 50,000 条目、48 层和 8 秒预算，单次文件系统调用不保证可中断。权限、路径变化或预算耗尽时明确标注结果不完整、未读取空间未知，并保留已测得的部分。扫描可取消，关闭面板取消工作，结果不持久化。固定扫描使用 descriptor-relative 系统调用，不通过 shell 或外部扫描器。

**职责边界**：Augma 面向整机与文件使用，提供空间分析、定位和检查建议；Craft Hub 持有项目注册、信任、维护命令与执行记录。已在项目区域配置 Craft Hub 只读连接时，可在分析页主动刷新已共享项目；进入匹配的项目目录后，通过「在 Craft Hub 维护项目」打开现有导航入口。此动作只读项目上下文，不执行命令、不授予信任。未连接时分析功能仍独立可用。已有 Git 项目引用可定位项目；无可分享引用的本地项目打开工作台后需手动选择。未安装或连接失败有明确反馈。

自动化验证使用 `swift test --package-path apps/mac --filter DiskUsageTests`，覆盖临时目录中的大小口径、硬链接、稀疏文件、符号链接、权限、限额、路径替换、取消、过期结果、目录下钻、项目路径匹配、区块图面积和原生深浅色渲染。设置 `AUGMA_RENDER_DISK_USAGE_DIR` 可保存渲染图；不扫描真实个人目录。

## 系统监控与天气

监控面板提供「清理磁盘与内存」。磁盘扫描仅在点击时执行，检查 `~/Downloads` 顶层的 `.dmg` / `.pkg` / `.xip` 安装包，以及 `~/Library/Developer/Xcode/DerivedData` 的独立构建缓存；只列出整个项目至少 7 天未修改且完整读取的候选，默认不勾选。每次最多检查 50,000 个条目、8 秒并展示 100 项，权限不足或超限会标注结果不完整。不会向外遍历符号链接，也不跨文件系统；执行前重新检查路径、文件身份与后代元数据，变化项跳过。选择后确认移入 macOS 废纸篓，可在 Finder 恢复；移入废纸篓不会立即释放空间，需要用户自行确认后清空，Augma 不代为清空。Xcode 缓存重建会耗时。

内存整理复用现有应用排行与压力读数，逐个确认后请求应用正常退出；应用可以等待保存或拒绝退出，不强制终止、不清除交换文件，也不承诺回收特定字节数。请求前复核 PID、应用路径和启动时间，禁止退出 Augma 本身；可打开活动监视器进一步检查。

清理面板还提供 Homebrew 官方接口：主动预览后，显示原始报告、候选项数与 Homebrew 的近似容量估算。当前验证 Homebrew 7.x；未知版本、未知报告格式或检测到 `brew.env` 环境配置时只提供预览。固定从 `/opt/homebrew/bin/brew` 或 `/usr/local/bin/brew` 调用，不自动安装，不拼接 shell；设置 `HOMEBREW_NO_AUTOREMOVE=1`，禁用自动更新、分析上报与 sudo。预览和执行都有 45 秒超时与合计 256 KiB 输出上限，不创建后台轮询。

Homebrew 清理需要单独确认永久移除：它会按自身规则处理旧版本、过期下载、日志及失效元数据，不能从废纸篓恢复，预览也不是完整、原子锁定的删除清单。执行前重新检查版本、预览与环境配置，预览超过 5 分钟或内容变化则要求重做。执行后分别显示命令成功/失败、原始报告和卷可用空间变化；后者包含其他应用并发写入，不能全部归因于本次操作。取消或失败时可能已有部分清理完成。不会调用 `autoremove`、`--prune=all` 或清空废纸篓。语义依据：[Homebrew cleanup 与环境变量](https://docs.brew.sh/Manpage)。

扫描后可使用「AI 清理建议」，复用「AI 助手设置」中明确启用的 DSH / Magpie 或 DeepSeek API 兼容后端。只有确认「发送摘要并分析」才联网，发送系统内存 / 磁盘数值、候选类别的数量与大小、最多十个匿名应用的占用及读取完整性；不发送文件名、路径、应用名、磁盘名称或内容。回复只允许建议文本、已有候选类别和本次摘要中的应用编号，不接收脚本或操作指令，不自动勾选或执行。关闭面板、取消或更改助手配置会取消请求并丢弃迟到结果；未配置、离线或请求失败时本地清理仍可使用。API 调用可能收费；建议反映发送时的快照，需要结合当前使用情况判断。

存在 Homebrew 预览时，AI 摘要额外包含条目数、可选的容量估算与“预览不完整”的标记，不包含工具原始报告、包名或路径。Homebrew 的执行入口仍由本地确认流程管理，模型不能直接调用。

清理面板还提供「模拟器专项清理」，无需安装 Mole。点击扫描后，通过 Xcode 的 `simctl` 读取默认设备集和系统共享运行时清单，分别显示容量估算、运行状态、最后使用时间及运行时在默认设备集中的关联设备数。设备容量使用工具报告的数据目录大小，运行时使用映像大小；不递归统计挂载卷，不重复相加运行时与挂载目录。未报告容量的项目显示未知，估算不代表承诺释放空间。缺少 Xcode、权限不足或无法识别的报告会显示原因，不会当作零占用。

设备图标复用公共 `Icons/` 模块，按真实型号优先查询系统官方图片，缺少时使用统一的设备符号；运行时显示平台标识。图标保留原色、比例和透明区域，不按用户修改过的名称猜测。新增页面的调用方式与缓存规则见[原生图标复用说明](../../docs/native-icons.md)。

默认不勾选项目。只有已关闭的设备，以及默认设备集没有关联设备、可由系统删除且默认设备集均已关闭的运行时，才可选择删除；未知状态只供查看。即使同时选择关联设备和运行时，也需先删除设备、重新扫描，再选择运行时。Xcode 预览、CI 和自定义设备集不在扫描范围内；运行时为全局资源，删除会影响其他设备集，确认时必须另外勾选已自行检查并关闭相关模拟器。未作这项确认时，执行接口也会拒绝运行时删除。「AI 建议」经确认只发送匿名编号、类别、容量和状态等摘要，不发送设备名称、UUID、路径或原始报告，并明确标记其他设备集未验证；AI 仅建议检查顺序，不改变选择或执行操作，未配置 AI 时仍可手动清理。

执行前需在原生确认面板逐项核对名称、类别和估算，并确认永久删除。设备中的 App、登录状态与测试数据会一起移除，不能从废纸篓恢复；运行时以后需要重新下载。确认绑定本次扫描及具体项目，五分钟后失效，执行前重新读取身份、状态和依赖；变化项跳过。删除仅调用固定 `simctl delete <UUID>` 或 `simctl runtime delete <UUID>`，不会批量删除全部设备、自动关闭其他模拟器或直接移除目录。运行时删除可能由系统异步完成，回执区分已删除、跳过、失败和等待系统完成，并显示同卷可用容量变化；该变化也受其他应用写入影响。扫描和 AI 可取消，关闭面板会丢弃迟到回复；已确认的删除执行期间需等待完成再关闭或退出。

侧栏「系统 → 系统监控」显示真实 CPU、内存、磁盘、网络和电池读数，也可按 `⌥⌘M` 或执行「打开系统监控」「查看网速」进入。CPU 显示总占用及用户 / 系统占比；内存显示已用、物理总量、压缩内存、交换空间和压力；磁盘列出启动数据卷与本地可见卷的容量；网络显示当前物理接口的实际上下行流量；电池显示电量、供电 / 充电状态与系统提供的预计时间。无内部电池的 Mac 显示相应说明。磁盘使用文件系统容量口径，与 Finder 包含可清理空间的估算可能有差异；内存排除可回收文件缓存。

「应用内存排行」按占用降序展示当前用户运行中的桌面 / 菜单栏应用、图标、进程数与比例条，默认显示前十名，可用原生玻璃按钮展开全部；菜单栏摘要显示前三名。嵌套 Helper、包内 XPC 与可确认父子关系的外部子进程按所属应用合并，同一应用的多个实例按应用路径汇总；从其他应用启动的独立应用仍分别统计。使用公开 `proc_pid_rusage` 的 `ri_phys_footprint`，不以 RSS 替代，包含压缩等内存记账；逐进程合计不等同于系统已用内存或全系统去重 RAM。条形以首位应用为基准。无法确认归属的共享系统服务（包括父进程已脱离应用的系统 WebKit XPC）不猜测归属；不可读取的已归属进程标注为部分不可读取，数值可能低估。进程退出、PID 复用和读取失败不会沿用旧排行。采样在后台执行，沿用现有可见性与休眠策略，不请求管理员权限。原生卡片与玻璃按钮搭配 Augma 静态环形标识、青色比例条。

主窗口、菜单栏摘要和 HUD 共用一个原生采集服务，不通过网页，不上传系统指标。设置窗口的「系统监控」页可选择仅手动刷新或 1 / 2 / 5 / 10 秒间隔、开关菜单栏摘要和固定 HUD。默认每 2 秒采样，磁盘每 30 秒刷新；手动刷新会重新读取磁盘。没有可见消费者时停止，休眠时暂停，恢复后重新建立 CPU / 网速基线。网络采用 64 位接口计数器，首样本、接口切换或失效基线显示不可用，不把累计流量当作当前网速；只选一个 Wi-Fi / 以太网物理接口，避免叠加 VPN 流量，暂不统计虚拟接口和 Thunderbolt Bridge。

「当前网卡流量」包含所选物理网卡的互联网和局域网通信，详情页显示网卡类型与接口名，菜单栏和 HUD 可悬停查看。每次采样优先使用系统物理默认接口；VPN 遮蔽默认接口时，按系统网络服务顺序选择当前已连接的物理服务，并优先选择有路由器的服务。已断开的链路不会被沿用，也不再按开机以来的累计流量选卡。未提供手动切换；VPN 虚拟接口和本机回环计数不额外累加，因此与活动监视器的全接口汇总可能不同。

监控详情采用自适应仪表卡片：可用宽度达到 656 pt 时以两列展示 CPU、内存、磁盘和电池，窄宽度回到单列，内容最大宽度 1040 pt。圆环与主数值位于卡片左侧，用户 / 系统占比、压缩内存、交换空间、容量和供电等细项在右侧对齐；卡片内部空间不足时纵向排列。控制区优先合并为紧凑横行，采集选项与统计说明按需展开。应用排行保留横条，网速以并排读数及可选曲线展示。布局继续读取同一份监控快照，未增加采样、计时器或历史缓存。320 / 480 / 768 / 1040 pt 的原生宿主离屏渲染及浅深色检查通过，宽布局显著减少概览高度，当前应用已验证四项指标同屏。全量 Swift 测试通过。

菜单栏、HUD 与监控详情使用 SwiftUI 原生 Gauge 搭配静态圆环，CPU、内存、磁盘与电池以实际占用 / 容量比例绘制；应用排行继续使用便于比较的横条。菜单栏显示启动数据卷占用与可用空间，详情页保留各卷读数。内存颜色由系统压力决定，不因 GB 数值或排行第一而告警；磁盘剩余空间不高于 10% 使用橙色、不高于 5% 使用红色；未接外部电源时电池不高于 20% / 10% 同样区分低电量，充电使用绿色。CPU 使用青色表示当前负载，负载高本身不判断为故障。暂停和不可用显示灰色，未知容量使用虚线环与缺失值，状态仍有文字可读。上传为蓝色、下载为青色，橙红保留给需关注的状态。圆环仅随现有快照重绘，没有额外定时器、持续动画或玻璃图层。本轮浅色 / 深色原生渲染、菜单栏 400 pt 宽度与 HUD 162 pt 高度检查通过，内存 / 磁盘 / 电池详情完成实际应用走查。

在监控面板的「采集选项」或设置的「系统监控」页，可分别开关应用内存排行、温度与风扇、网速历史曲线，并可用「启用系统监控」总开关暂停全部采集。新传感器和曲线默认关闭；已有应用排行默认开启。主窗口和菜单栏可见时按选择采集，只有 HUD 可见时跳过进程扫描、传感器与历史。仅手动刷新模式在界面首次可见时读一次，之后只响应「刷新」，没有重复定时任务；CPU 与网速仍需要相邻有效采样。所有消费者关闭、窗口隐藏 / 遮挡或休眠后，停止采样并释放排行、历史与读数缓存；下次打开从新基线采样，不连线跨越休眠与接口切换。设置页本身不触发采集。HUD 在监控与待命状态使用静态环形标识，避免为装饰持续绘制。

「温度与风扇」最快每 5 秒只读访问一次 AppleSMC，每次读取后关闭 IOKit 连接，不安装特权助手、不申请管理员权限、不控制风扇。CPU 温度使用已识别芯片的有效测点，Apple 芯片显示平均值，Intel 优先封装 / 芯片测点；排除无效及停用核心占位值。芯片键映射覆盖 Intel 与 M1–M5；AppleSMC 协议非 Apple 公开稳定接口，未知机型、系统限制或读取失败显示不可用，不以零代替。风扇正常停转显示 0 RPM，只有成功读取到风扇数为零才显示无风扇。协议与键映射参考 [Stats 的原始实现](https://github.com/exelban/stats/blob/master/SMC/smc.swift)和[传感器定义](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift)，Augma 仅实现读取。

网速曲线使用 SwiftUI Canvas 随新采样重绘，无独立动画或计时器，也不引入图表依赖。仅保留当前接口最近 120 秒、最多 120 个有效点，不写文件或上传；关闭曲线即释放历史。上传为蓝色、下载为青色，表示真实流量而非网络测速。

2026-10-26 在 Apple M5 Pro / macOS 26.6.2 上完成原生界面走查：成功读取 18 个有效 CPU 测点与两只风扇，硬件读取约 8 ms；曲线、独立开关、手动刷新和总暂停已验证。测试包含最后一个消费者关闭后超过刷新周期不再采样的检查。同次调试构建的 5 秒宿主进程采样：手动模式约 94.3 MiB / 单核 CPU 0.010%，总暂停约 90.1 MiB / 0.007%。这是整个宿主的短时观测，受界面缓存、系统压缩与机器负载影响，不能当作监控模块独占内存或长期基准；Intel、其他 Apple 芯片与 macOS 27 尚未完成真机验收。

在详情页或菜单栏勾选「固定系统监控到 HUD」后，独立窗口显示 CPU、内存、磁盘可用量、上下行速度和电量，固定内容不会让窗口始终置顶。关闭主窗口仍可使用 HUD，固定偏好会保留到下次启动；从 HUD、详情页、菜单栏或设置中取消固定都会立即隐藏窗口，「隐藏窗口」则保留固定偏好。HUD 使用通透的 Clear Liquid Glass，避免整块灰白磨砂底。状态栏图标保持静态，实时读数位于弹层和 HUD 中。

主窗口「天气」使用限宽居中的紧凑概览：突出当前温度和天气图标，最高 / 最低温并入天气摘要，体感、湿度与风速横向排列。更新时间和刷新入口位于卡片右上角，悬停时间可查看天气时间和获取时间。「我的城市」使用自适应卡片，支持切换、通过卡片菜单删除及重启恢复；「添加城市」在原生弹出面板中搜索，旧版最近选择和天气缓存会自动保留。排版参考 [Clima](https://dribbble.com/shots/26240563--Clima-dashboard) 的指标分组和 [Minimal Weather Widget](https://dribbble.com/shots/25580019-Minimal-Weather-Widget-UI) 的紧凑层级，图标继续使用原生 SF Symbols。

手动选城无需定位权限；点击「使用当前位置」才请求 macOS 定位授权，获取一次大致位置，由 Apple 解析城市名，不持续跟踪。定位失败仍可手动添加城市；重新打开页面仅使用上次保存的位置，不自动重新定位。

数据来自 [Open-Meteo](https://open-meteo.com/)，无需 API Key；发送搜索词和城市坐标，定位坐标取小数点后两位。城市、最后选择和天气缓存保存在本机，切换城市优先复用各自缓存。缓存 15 分钟，每城手动刷新间隔至少 1 分钟，离线或服务错误时保留上次读数并标注时间。免费接口[仅限非商业用途](https://open-meteo.com/en/terms)，页面「数据来源」附 Open-Meteo / CC BY 4.0 / GeoNames 署名。当前值是气象模型的估计，非设备传感器温度；CPU 温度由可选的「温度与风扇」监控提供，与天气数据独立；暂未接入 GPU 温度。

Apple Weather 可通过 [WeatherKit](https://developer.apple.com/weatherkit/) 接入，需要 Apple Developer Program 会员和应用能力配置，本版本使用 Open-Meteo。沉浸模式复用同一原生天气、记录、计时、系统监控、声音、设置、地图和摄像头面板，并通过共享空间 Store 呈现 RealityKit 场景。通知、助手和设备均直接使用原生状态。

## 语音指令

主窗口的语音面板包含原生 SwiftUI 环形动效与橙青色声纹：聆听时使用麦克风 RMS 音量驱动，等待权限、识别及助手处理时显示处理中动效。音量在音频回调中限频到每秒约 20 次，经平滑后直接交给原生小视图，不经过网页、不保留音频副本。待命与非活动状态停止语音时间动画，隐藏的辅助 HUD 也停止环形动画，开启系统「减少动态效果」后改用静态图形和音量进度条。面板中的「预览语音动效」可切换待命、聆听、处理状态并调整示例音量，不会使用麦克风。

在主窗口侧栏打开「语音指令」，点击「开始语音识别」，说出指令后点击「结束并执行」；也可直接输入文字并点击「执行」。主窗口工具栏和菜单栏麦克风打开原生快捷指令窗并开始录音。沉浸模式左上角麦克风打开原生语音助手面板，点击开始后才录音；右上系统菜单还可打开快捷指令。也可在 App 内按 `⌥⌘V`（「语音」菜单）打开指令面板并开始录音，再按一次结束并执行；等待权限或识别结果时再次按下会取消。默认不用 `⇧⌘V`，因为 Paste、Pastebot 等剪贴板工具把它注册为全局快捷键，按下后 Augma 收不到。要换成其他按键，可在「系统设置 → 键盘 → 键盘快捷键 → App 快捷键」中为 Augma 添加菜单标题「开始或结束语音指令」（English 界面为 “Start or Finish Voice Command”，日本語界面为「音声コマンドを開始／終了」）；演示界面的快捷键列表和指令面板会显示菜单当前的按键。首次使用时，macOS 会请求麦克风和语音识别权限。语音识别由系统 Speech 框架完成，识别语言跟随演示界面当前的语言（简体中文、English 或日本語）：设备支持该语言的离线识别时优先在设备上处理，否则可能使用 Apple 在线识别服务。日常快捷指令窗与沉浸模式的原生快捷指令面板一次录音最多约 60 秒，单独的演示语音面板仍为约 12 秒；切换到其他 App 或关闭指令窗会停止录音。日常面板识别语言跟随 App 语言，演示面板跟随演示语言。

日常指令之外，演示语音面板还支持打开地图、扫描空间、查看当前播放信息、显示或隐藏 HUD、打开天气 / 通知 / 设置 / 摄像头 / 网页面板、切换深色或浅色视界，以及对当前选中地点开始模拟导航、前进一步、结束导航。语音不会自行开启摄像头。识别文字会显示在面板中；也可以手动输入指令或点击示例按钮，不需要麦克风。在浏览器中打开的网页演示改用浏览器自带的语音识别，点击开始后才请求麦克风权限。执行后会用 原生 AVSpeechSynthesizer朗读结果或助手的回复，可在演示设置中关闭「语音播报」；开始录音时会先停止朗读，避免被麦克风收进去。

## 多语言

在主窗口「设置」或 App 设置窗口「外观与语言」中选择「应用语言」。默认选择「跟随系统」，也可手动指定简体中文、English 或日本語。主窗口、设置、菜单栏、悬浮窗口、沉浸面板、原生提示、助手识别与内置插件使用同一个选择，重启后保留。切换只更新语言，不重建窗口或清空编辑状态；打开的呼吸环也不会重置练习。「跟随系统」保存的是跟随模式，按当前系统语言解析；系统语言变化或 App 重新激活时刷新，恢复默认也回到跟随系统。已有手动语言偏好继续保留。系统管理的权限弹窗遵循 macOS 的 App 本地化选择，普通浏览器仍自行保存网页语言。

字符串表位于 `apps/mac/Localization/*.lproj`，以 Swift 源码中的简体中文原文为键，由 `script/build_and_run.sh` 复制进 App 包。SwiftUI 根视图通过 `appLocalized()` 接收语言环境；服务、错误和命令标签通过 `String(appLocalized:)` 或 `NativeLocalization.string` 取值。AppKit 标准菜单保留原菜单项、动作和快捷键，只刷新标题。`pnpm i18n:check` 检查三语键、静态引用、空翻译与格式占位符；此检查也进入 `pnpm test:release` 和 `pnpm check`。Swift 测试另外覆盖插值、偏好恢复、并发语言隔离、菜单动作保留和真实 WebKit 的语言切换。

日常快捷指令始终只在本机匹配。演示助手也先匹配本地指令；文字输入与系统语音识别的最终文字共用同一入口。未匹配的问题才会交给明确启用的 AI 运行时。本地指令、记录、计时、扫描与清理确认不依赖模型可用性。

### DSH / Magpie 助手

新配置默认选择 **DSH / Magpie**，默认不开启发送。已保存过 DeepSeek 开关的安装（包括显式关闭）继续保留该选择，钥匙串条目不会迁移或删除。

1. 自行安装可用的 **DeepSeek Harness 0.2.0-rc.2**，在 Magpie 中完成登录、模型来源和路由配置，并启动本地网关。网关联调覆盖 Magpie 0.1.1293；应用列表和推理强度管理通过官方 Magpie 0.1.1673 的独立插件验证。
2. 打开「设置 → 助手」，选择 DSH / Magpie。路径留空会检测已安装的运行时，也可填写完整可执行文件路径。macOS 桌面版的入口为 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`。旧的 `~/.local/bin/dsh` 可能只是失效 shim；仅能找到命令不代表能运行。
3. 点击「检测连接与模型」，选择 DSH 会话实际公布的模型和推理选项。模型标签显示路由 ID；切换模型后重新检测推理选项。首版仅开放 Magpie 路由，不继承 DSH 桌面端的其他 provider 或工具配置。
4. 点击「测试模型与只读工具」。这会发送一次模型请求，并让模型读取真实系统摘要、应用名称和占用，可能消耗所选模型额度。两项工具均成功后，单独打开「启用 DSH 助手」。修改路径、模型或推理选项会清除测试状态，需要重新测试。

Augma 通过 ACP over stdio 启动自己拥有的 DSH 无界面进程，不打开 DSH 桌面窗口、不自动安装或升级。DSH 管理模型上下文、工具循环与压缩。Augma 只传当前任务，不把用于显示的最近四轮记录重放给 DSH；首版显示消息级进度与工具状态，不提供逐 token 输出。每个窗口和清理业务有独立会话，共享一条进程连接。闲置 60 秒释放连接；下次任务可恢复本次 App 运行期间的空闲会话。取消、关闭窗口或更改配置结束旧任务，下一次取消后任务使用新会话。App 重启后不自动恢复旧聊天窗口或会话映射。

原生工具仅包括 `system_summary`、`application_usage` 与 `open_panel`。前两项读取内存压力、交换空间、磁盘容量和最多十个应用名称、近似占用及读取完整性；不读取文件内容、路径、网页标签或进程命令行。打开面板只作用于当前窗口，不开启摄像头、不导航网址。模型没有任意 shell、文件写入、结束应用、删除文件或清理命令工具。清理建议仍使用用户确认后的匿名数字摘要，并校验类别与应用编号；模型不能选择、确认或执行清理。

Augma 使用专属运行 profile 和 `~/Library/Application Support/Augma/Assistant/Sessions` 保存 DSH 会话；不修改 DSH 全局/桌面 profile，不复制 Magpie 登录凭据。Magpie 的本地 `magpie-augma` 标记用于应用用量归属，不是订阅密钥。会话文件可能包含已发送的问题、工具结果和回答，留在本机；此版本没有自动保留期限或跨 App 重启的聊天历史浏览器。关闭 Augma 会回收其子进程，不结束用户原本运行的 DSH 或 Magpie。

安装 [Augma Magpie 插件](../../integrations/magpie/README.md) 后，官方 Magpie 的应用列表会显示 Augma；卡片中选择模型或路由组，Agent 页底部的「Augma 推理强度」面板保存推理强度，不增加独立导航 tab，无需修改 Magpie 源码。Augma 导出不含凭据的 `~/Library/Application Support/Augma/Assistant/magpie.json`，并在受管理时读取插件自己的推理强度设置。返回 Augma 或检测连接时同步新选择，变更会取消旧请求并清除测试状态，需要重新测试和启用。断开管理恢复接入前的配置。当前已验证 `group/augma` → GPT-6.1 Terra / Medium，继续复用本机 DSH。

检测失败会区分运行时缺失、入口失效、未验证版本、Magpie 未运行、无模型及模型不可用。请求失败提供鉴权、额度、超时或通用任务错误；不展示可能含私密内容的 provider 原始错误，也不静默改用另一条付费路由。当前仅固定验证 DSH 0.2.0-rc.2，其他版本会被拒绝，需先更新兼容验证。

## 原生界面验证

Codex 清理回执和 Craft Hub 连接的持久化测试使用真实临时文件与注入式写入器，隔离 macOS 数据保护密钥包在锁屏或解锁异常时的权限变化。正式写入仍使用原子替换和 `completeFileProtectionUnlessOpen`，清理回执仍限制为 `0600`；独立回归验证保护选项，以及密钥包不可用时保存报错、清理不移动文件。

只构建而不退出或启动现有 App，可运行 `./script/build_and_run.sh --build`。独立验收包可通过 `AUGMA_APP_BUNDLE`、`AUGMA_BUNDLE_ID`、`AUGMA_APP_DISPLAY_NAME` 和 `AUGMA_BUILD_CONFIGURATION=release` 配置；独立标识不会注册日用版的登录回调。普通重建只退出目标包路径对应的进程，不再按进程名退出所有 Augma。验收资料可通过 `open --env CFFIXED_USER_HOME=<目录>` 隔离，外部网易云播放队列仍从当前系统用户的目录只读获取。

`pnpm mac:verify` 构建并启动 `.app` 后检查主窗口；`swift test --package-path apps/mac` 检查原生服务、快捷键、共享状态、音量采样与菜单会话路由。其中持久化测试使用独占临时目录，覆盖重启、连续输入、计时暂停恢复、睡眠/时钟校准、编辑冲突、写入失败重试和损坏恢复。空间测试使用注入的单调时钟，覆盖扫描完成与取消、锚点所属地标、模拟路线、视角边界及窗口间状态隔离；不测试或声称真实环境扫描。地图测试注入客户端，覆盖搜索、路线失效、取消与过期结果、地图交接参数，以及后台路线回调；摄像头测试注入权限和采集后端，覆盖显式授权、取消、窗口交接、设备断开、拍照和保存错误，不打开实际设备。语音指令测试注入识别事件，音量测试使用合成 PCM 数据，不打开麦克风。浏览会话测试验证地址解析、脚本隔离和宿主切换；助手测试验证有限历史、白名单、取消和迟到回复。独立 AR 网页的测试继续覆盖浏览器端行为。摄像头、麦克风权限与真实设备能力仍需在目标 Mac 上验证。

## Dock 自定

「设置 → 外观与语言 → Dock」可将底部间距调整为 0–120 pt，即时应用到 Augma 布局与沉浸模式，并在重启后保留。默认 17 pt，与顶部控件到菜单栏的可见间距一致；「与顶部间距一致」可随时恢复该值。沉浸模式以当前屏幕的可用区域为准，为系统 Dock 保留空间；内容面板随间距调整，避免与 Dock 重叠。

沉浸 Dock 在四周为 Liquid Glass 阴影保留透明绘制空间，避免阴影被浮窗矩形边界截断。这部分不计入可见底部间距，也不会拦截下方窗口的点击。原生截图回归使用 `AUGMA_RENDER_DOCK_DIR=/tmp/augma-dock swift test --package-path apps/mac --filter NativeDockLayoutTests`，验证浅色、深色及缩小后的 Dock 边缘透明度和点击穿透。

Dock 名称提示使用系统 Liquid Glass 圆角气泡，随窗口切换浅深色，并在屏幕边缘限制长标题宽度。首次悬停等待 200 ms；提示出现后，在同一 Dock 内切换图标立即更新，跨越图标间隙不会重复等待。移出 Dock、点击、拖拽或窗口隐藏时收起提示。`AUGMA_RENDER_DOCK_DIR=/tmp/augma-dock swift test --package-path apps/mac --filter DockTooltipTests` 验证提示切换、取消、独立 Dock 隔离和真实窗口的气泡边缘。

Dock 随图标数量扩展，直到达到当前窗口或屏幕的可用宽度；沉浸模式左右各保留 20 pt。宽度用满后，图标、间距和留白按比例缩小，不出现横向滚动条。图标数量不设固定上限，应用、内置功能和插件均可继续添加；较少图标保持紧凑显示。排列在不同宽度和重启后保留。

主窗口与沉浸模式的底部 Dock 支持拖拽排序：移动时预览位置，松手后保存；按 Escape 或拖到 Dock 外松手会取消。右键图标的「选项」包含「从 Dock 中移除」「在访达中显示」及向左／向右移动。内置功能和网页入口在访达中定位到 Augma.app；本机应用入口定位到对应的应用安装包。右键 Dock 可通过「添加到 Dock」恢复移除的入口，或「恢复默认 Dock」重置；全部移除后仍保留「自定 Dock」按钮。排序和显隐在多个主窗口、沉浸模式间共享，并在重启后恢复。

## 应用街区

在「空间 → 应用街区」中，点击「添加应用…」选择 VS Code、Chrome 等已安装 macOS 应用，支持一次选择多个；空白街区提供常用已安装应用的快捷入口。RealityKit 大楼显示应用图标和名称，点击大楼或列表中的打开按钮启动应用或切换至已有应用。运行中、当前前台、未运行和缺失状态来自 NSWorkspace 系统事件；不读取项目文件或浏览器标签页。沉浸模式中打开应用成功后会隐藏助手，重新唤起保留当前场景。

街区有 12 个地块，可自定义名称、固定位置、交换位置、移除和撤销上一次移除，也可重新排列未固定大楼。固定的大楼不会被其他大楼挤动；移除入口不会卸载应用。布局保存在 `~/Library/Application Support/Augma/application-district.json`，主窗口、多个窗口和沉浸模式共用应用级布局及运行状态。保存失败可重试，损坏文件仅在用户选择重建时备份后替换。

应用身份使用 bundle ID，重新选择同一应用会更新路径并保留布局；原路径失效时通过系统查找相同标识的应用。应用丢失或启动失败会保留大楼并提示，不会跳到同名的其他应用。布局和运行状态测试使用可注入客户端，文件测试在独占临时目录中验证原子保存、重启恢复和损坏保护，不启动真实应用。

选中大楼后可在「应用管理 → 在 Craft Hub 查看卸载指引」跳转到软件中心。需要支持卸载指引入口的 Craft Hub；未安装或无法打开时显示错误，应用街区仍可独立使用。跳转仅通过 `craft-hub://software?v=1&bundleId=…`（或原生候选版协议）传递应用标识，不需要 Agent 连接，不传递应用路径，也不执行卸载或清理。Craft Hub 负责展示同一标识对应的本机副本、卸载程序候选及说明来源；候选只提供 Finder 定位。

## 项目区域

在「空间 → 项目区域」添加项目文件夹，绑定本机 VS Code、Google Chrome 和工作网址。最多保存 6 个区域，每个区域最多 10 个 HTTP(S) 网址，支持 localhost。点击三维区域查看入口；点击「打开工作区」保存当前配置并在 VS Code 新窗口打开项目，然后在 Chrome 打开网址。每项显示打开结果，部分失败可只重试失败项，取消会停止后续请求。浏览器接受请求后显示「已打开」，页面加载结果由浏览器显示。

配置、编辑草稿和打开结果在主窗口与沉浸模式之间共享；配置写入 `~/Library/Application Support/Augma/project-regions.json`，重启后恢复。文件夹使用系统书签，失效时可重新绑定。保存失败可以重试，无法读取的配置不会自动覆盖。项目区域支持命名、位置交换、移除和撤销，移除不会删除项目文件。打开成功会收起沉浸助手，有失败项则保留结果。

VS Code 使用绑定安装包中的 CLI 和独立路径参数，不要求安装终端 `code` 命令；Chrome 使用 NSWorkspace。原生测试使用注入客户端验证批量打开、部分失败、重复点击、取消、迟到结果和共享草稿，真实临时目录验证书签与持久化，不启动外部应用。

[空间工作区方案](docs/workspace-world.md)记录了应用大楼、项目区域，以及后续 AI 场景生成设计。当前只打开已绑定的项目和网址，尚未接入 AI 三维生成，也未同步 VS Code 当前项目或 Chrome 当前标签。

### 可选连接 Craft Hub

在 Craft Hub 的「设置 → Agent 连接」选择共享项目并启用只读访问，复制 **MCP · JSON**。在 Augma 的「空间 → 项目区域」选择「从 Craft Hub 添加…」，或在已有区域选择「绑定 Craft Hub 项目…」，粘贴配置、选择项目并确认。无需启用插件读取，也不需要在 Augma 中安装 Node 或运行 MCP 命令。

连接后，区域名称、项目目录、信任状态及命令／技能摘要来自 Craft Hub；应用选择、工作网址和三维布局由 Augma 保留。摘要最多展示前八项能力，并显示完整命令／技能数量。「在 Craft Hub 中查看」使用项目的 Git 引用导航；没有 Git 引用时打开 Craft Hub 首页。打开工作区前会重新读取项目资料，随后仅打开编辑器与已保存网址，不执行项目命令或授予信任。

连接失败、授权撤销或项目移除时保留区域，显示需要重新连接或更换绑定的原因，不自动使用过期目录。「解除绑定，使用本地配置」恢复原来的区域名称和文件夹，应用、网址和布局保持不变。独立添加的区域不依赖 Craft Hub。不同配置源中的同名或同 ID 项目不会自动替换绑定。

连接保存于 `~/Library/Application Support/Augma/craft-hub-connection.json`，只包含本机地址和授权文件路径，不保存令牌。令牌由 Craft Hub 管理，每次读取时使用当前凭据；项目资料只缓存在本次会话中。Craft Hub 关闭后连接不可用；端口变化时重新粘贴当前配置，同一凭据来源的区域绑定会保留。Augma 断开连接不影响其他客户端；要撤销所有使用该授权的客户端，请在 Craft Hub 撤销连接。

项目区域文件升级为 v2，兼容读取 v1 的独立项目；旧版 Augma 会拒绝覆写 v2。自动化验证：`swift test --package-path apps/mac`。跨仓库真实宿主验证：`node script/verify-craft-hub.mjs /absolute/path/to/craft-hub`，需该仓库已安装依赖；脚本使用独立临时数据、原生宿主门禁和真实 Swift HTTP 客户端，结束时撤销测试授权、关闭宿主并验证进程退出。
