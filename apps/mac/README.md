# Augma macOS

macOS 主窗口默认使用 Augma 布局：左上语音入口、顶部时钟、右上系统按钮和底部圆形 Dock，中间展示原生应用内容。工具栏的布局按钮或 `⌥⌘0` 可切换为 SwiftUI 侧栏布局；选择会保存，主窗口之间共享布局偏好。两种布局共用窗口级 Store，切换不会清空笔记、网页、语音输入或空间状态，默认打开「快速记录」。日常功能包含快速记录、专注计时和快捷指令；系统监控、真实天气、声音播放与场景设置也独立在原生端运行。空间、摄像头、导航、通知、语音指令和设备面板中的按钮、开关、滑块、选择器、输入框与确认对话框均为原生控件。窗口跟随 macOS 的浅色 / 深色外观与辅助功能设置；macOS 26 及以上由系统提供 Liquid Glass 工具栏，辅助 HUD 的浮动按钮也使用系统玻璃样式，macOS 15 回退到标准按钮与原生材质。Augma 环形标识保留在品牌区和空间内容中。

空间采用「RealityKit 场景预览 + 原生控制面板」布局，庭院、城市、虚拟地标、模拟扫描、锚点和模拟路线均在原生端运行。「导航」使用 MapKit，「摄像头」使用 AVFoundation，声音使用 AVAudioEngine。通知、语音助手和设备面板也直接使用 Swift 状态。所有应用功能都不再加载内部网页，不包含隐藏 WebView、网页状态桥或打包的 AR 站点；只有用户主动打开的「网页」功能使用独立 WebKit 会话。

`NativeDemoModel` 持有窗口级的空间、通知、设备、助手与浏览会话，主窗口和沉浸模式注入同一组 Store。扫描与音频进度由小视图直接订阅。浏览器版本的 AR 演示继续独立维护，macOS 构建不依赖它。

按 `⌘1`–`⌘9` 或使用菜单栏的「应用」菜单可切换应用。主窗口使用原生菜单快捷键；语音保留 `⌥⌘V`。视界设置中的主题仅改变场景，原生窗口跟随系统外观。主窗口与其沉浸模式共享同一窗口级空间 Store，保留场景、扫描、锚点、模拟路线和视角；各自的 RealityKit 渲染视图从同一状态恢复。所有窗口与菜单栏共用原生设置、音频、地图和摄像头服务，不同主窗口的场景选择、镜头与模拟空间状态各自独立，应用街区的建筑和布局在应用级共享。

点击 Augma 布局右上角或侧栏布局工具栏的「沉浸模式」，界面会以透明悬浮层覆盖当前显示器的可用桌面区域。原窗口暂时隐藏，退出后恢复。空白区域默认允许点击穿透，应用面板和按钮仍可操作；左上角保留语音助手入口，顶部中央显示时钟，右上角提供通知、设置、系统菜单和退出按钮。底部原生圆形 Dock 可切换天气、声音、空间、摄像头、导航和网页，也保留镜像、HUD、GitHub 与文档入口。右上系统菜单包含全部模块及「操作桌面」／「操作界面」切换；操作桌面时角落按钮和 Dock 仍可点击。可按 `⌃⇥` 在内容、Dock、语音入口和右上控制区之间切换键盘焦点。内容区域为顶部按钮和底部 Dock 留出空间，网页不会遮挡它们。菜单栏中的 Augma 菜单也提供这些操作。应用面板使用失焦后仍保持模糊的原生材质；Dock 和角落按钮在 macOS 26 上使用 Liquid Glass，失焦后同样保持模糊，在 macOS 15 上与应用面板使用同一种材质。

Augma 运行时，默认全局快捷键 `⌃⌥A` 可从任何应用唤起／隐藏沉浸助手。首次唤起使用最近活动的主窗口；主窗口已关闭时会创建一个。隐藏时主窗口不会弹出，当前内容与浏览会话仍保留，空间与摄像头视图会卸载、语音识别停止、网页媒体暂停；再次唤起恢复同一状态。`Esc` 或右上退出按钮则结束沉浸模式并恢复主窗口。在「Augma → 设置 → 窗口与快捷键」中可选择 `⌃⌥⌘Space` 或关闭全局快捷键；注册冲突会显示错误并允许重试。该快捷键使用系统热键注册，不依赖键盘监听或辅助功能授权。菜单栏的「沉浸助手」和状态栏「更多」也提供唤起／隐藏入口。


需要 macOS 15、Node.js 24 和 pnpm。在仓库根目录运行 `pnpm mac:run` 可打包并启动；运行 `pnpm mac:verify` 可额外检查进程和演示窗口。两条命令都调用 `script/build_and_run.sh`。脚本直接构建 SwiftPM 可执行文件并打包为 `apps/mac/dist/Augma.app`，不运行 Vite 或打包 AR 网页资源。Node.js 仅用于版本号和图标清单校验；也可直接运行 `./script/build_and_run.sh --verify`。原生功能离线可打开；地图、天气、网页和在线助手按需联网。运行 `pnpm mac:package` 则构建 Apple 芯片与 Intel 通用的 Release 版本，进行 ad-hoc 签名并压缩为 `apps/mac/dist/Augma-macOS.zip`（附 `.sha256`），版本号取自根目录 `package.json`。

App 图标是深蓝底板上的白色字母 A，外围是与原生 `AugmaRing` 同款的环形 HUD：青色细环和两段相对的圆头橙色弧。原稿归档在 [YunLeFun/icons](https://github.com/YunLeFun/icons/tree/main/assets/apps/augma/v1)（`ylf:augma-app-icon` / `ylf:augma-mark`），`assets/brand` 保存固定版本的副本与同一份 SHA-256 清单：`pnpm icons:check` 校验本地副本，`pnpm icons:sync --source /path/to/YunLeFun/icons` 从中心原稿更新。打包脚本先校验清单，再用 Xcode 26 及以上的 `actool` 把分层的 `Augma.icon` 编译为 `Assets.car`，供 macOS 26 的默认、深色、Clear 与着色外观使用；`AppIcon.icns` 由 `augma-app-icon.svg` 按 Apple 1024 px 模板渲染，作为 macOS 15 和旧工具链的兜底。

菜单栏右侧的 Augma 图标使用原生 `MenuBarExtra` 下拉面板，可直接输入并保存记录、查看倒计时、暂停 / 继续 / 延长 / 结束计时，以及打开快捷指令和语音输入。图标保持静态，秒级更新只发生在计时读数中，避免状态栏图标反复栅格化。菜单中的「更多」保留演示应用、播放控制、窗口置顶、设置、辅助 HUD 和鼠标穿透入口。操作优先定位最近使用的主窗口并恢复最小化窗口；主窗口关闭后会重新打开到所选面板。HUD 浮窗在 macOS 26 上使用 Liquid Glass，RealityKit 场景只在用户主动进入演示空间时创建。

主窗口工具栏和菜单栏都提供「始终置顶」开关；开启后演示窗口会显示在其他普通窗口上方，设置会在下次启动时保留。辅助 HUD 使用普通窗口层级，仅在所属桌面显示，不受主窗口置顶开关影响；沉浸模式仍使用悬浮层。

桌面版摄像头使用系统 AVFoundation 权限，不通过 WebKit；原生相机预览不提供 ARKit 世界追踪或真实环境扫描。空间使用 RealityKit 的非 AR 渲染，不申请摄像头权限；已移除空间透明 WebView 及其非公开背景设置兼容。WebXR 仅保留在普通浏览器演示中，内置网页浏览器不继承原生摄像头或语音权限，也不接入原生动作桥。推送 `v*` 标签时，发布工作流会把同一个压缩包附加到该版本的 GitHub Release，站点的[下载页](https://augma.yyj.moe/guide/macos)指向最新版本。安装包尚未使用 Developer ID 签名和公证，首次打开需在「系统设置 → 隐私与安全性」中点击「仍要打开」。

## 日常功能

- **快速记录**：统一输入入口，选择「笔记 → 备忘录」或「待办 → To Do」。笔记通过 macOS 自动化写入备忘录默认账户的默认文件夹；待办通过 Microsoft Graph 写入所选清单。主窗口和菜单栏共用草稿、目标偏好与发送状态。先将内容保存到本地再发送，收到成功响应后移出本地列表；失败保留内容，可编辑、重试、复制和导出 Markdown。无法确认发送结果时要求先检查目标应用再重试，以免重复创建。旧版本的本地记录保留，可逐条转存，不会自动上传。每条记录上限 20,000 字符。
- **专注计时**：25 分钟专注 / 5 分钟休息快捷入口，自定义分钟数，暂停、继续、延长 5 分钟、结束和完成历史。可打开始终置顶的紧凑计时窗。关闭主窗口不会退出应用，计时服务仍继续；退出 App 后保留截止时间，重新启动时恢复或补记完成。睡眠与系统时间调整后按绝对截止时间校准，不通过累加 UI 刷新次数计时。
- **快捷指令**：独立窗口与主窗口面板，支持搜索、方向键选择、Return 执行和最近使用排序。文字与语音走同一组原生操作；「记下 明天买咖啡豆」发送到备忘录，「待办 明天买咖啡豆」发送到 To Do，也支持 `note` / `todo` / `task` 和「メモ」/「タスク」。还支持「专注二十五分钟」「计时 30 秒」「暂停计时」「继续计时」「延长五分钟」「撤销」。外部发送不支持本地撤销，收到的即时反馈表示已排队，最终结果在快速记录中查看。该面板是 Augma 内置操作入口，目前没有集成 Apple「快捷指令」App。

App 内快捷键：`⌘⇧N` 打开记录，`⌘↩` 发送当前记录，`⌘K` 打开快捷指令，`⌥⌘F` 打开专注计时，`⌥⌘V` 开始 / 结束语音。这些是 App 菜单快捷键；在其他 App 工作时使用菜单栏入口。

草稿、待发送 / 失败内容、旧版本记录、计时和最近操作保存在 `~/Library/Application Support/Augma/workspace.json`，与 WebView 存储独立。格式 v2 兼容迁移 v1，旧版 App 无法覆写 v2 文件。文件由专用 actor 串行写入，草稿合并 300 ms 内的输入，原子替换并保留上一份有效 `.backup`（备份可能仍含刚发送的内容）。退出前等待本地写入；发送中退出或恢复备份后，未确认结果的条目不会自动重发。失败时保留内存数据并提示重试或导出；损坏文件不会被空数据覆盖，恢复备份前另存原文件。已发送内容由备忘录或 To Do 管理，Augma 暂不读取完成状态或进行双向同步。

### 连接备忘录与 Microsoft To Do

在快速记录的「连接设置」或 App 设置的「快速记录」页配置。备忘录首次发送会请求「自动化」权限；拒绝后可在「系统设置 → 隐私与安全性 → 自动化」允许 Augma 控制备忘录。请先在备忘录中配置默认账户；选择 iCloud 账户时，设备间同步由备忘录负责。内容以转义后的 HTML 写入，原始记录不作为脚本代码执行。

Microsoft To Do 使用系统浏览器登录会话、OAuth 授权码 + PKCE 和 `state` 校验，只请求 `Tasks.ReadWrite` 与 `offline_access`，不需要 Client Secret。刷新凭据保存在 macOS 钥匙串，访问令牌只留在内存；工作区 JSON 和 UserDefaults 不保存令牌。发送时绑定账户连接标识及清单 ID，换账户或清单失效后需要主动选择「改用当前目标重试」。

开发者需要为 Augma 注册一个 Microsoft 应用（此仓库不包含共享 Client ID）：

1. 打开 [Microsoft Entra 应用注册](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade)，登录有应用注册权限的账号，并确认右上角所选目录。点击「新注册」。如果账号没有可用目录或注册权限，需要先由该目录管理员提供访问权限。
2. 名称填写 `Augma`；受支持的账户类型选择「任何 Entra ID 租户 + 个人 Microsoft 账户」（旧版界面为「任何组织目录中的账户和个人 Microsoft 账户」），以支持个人 To Do 和组织账号。
3. 在同一表单的「重定向 URI」中选择 **公共客户端/本机（移动和桌面）**，填写 `msauth.cn.yunyoujun.augma.desktop-demo://auth`。查看页面链接的 Microsoft 平台策略后点击「注册」。也可以先留空，在注册后的「身份验证 → 添加平台 / 添加重定向 URI → iOS / macOS」中填写 Bundle ID `cn.yunyoujun.augma.desktop-demo`，生成同一回调地址。
4. 注册完成后，在「概述」复制 **应用程序（客户端）ID / Application (client) ID**。这是形如 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` 的公开 UUID；不要复制对象 ID 或目录（租户）ID，也不需要创建客户端密码 / Client Secret。
5. 打开「API 权限 → 添加权限 → Microsoft Graph → 委托的权限」，搜索并勾选 **Tasks.ReadWrite**，点击「添加权限」。这项权限允许应用读写当前登录用户的任务和清单；不要选择 `Tasks.ReadWrite.All` 应用程序权限。`offline_access` 由 Augma 登录时请求，用于保持连接。组织账户是否允许用户同意取决于管理员策略。
6. 在 Augma 中打开「快速记录 → 连接设置 → 开发者配置」，粘贴 Client ID，点击「保存应用 ID」。也可以从「Augma → 设置 → 快速记录」进入。该配置保存于本机，无需重新构建。
7. 点击「登录 Microsoft」，使用实际管理 To Do 的账号登录并确认授权。返回 Augma 后，等待清单加载，选择「待办清单」。快速记录切换为「待办 → To Do」后即可发送；没有 Client ID 的构建仍可使用备忘录，待办内容会保留在本地等待配置后重试。

发布时可将同一个公开 Client ID 内置到 App，在仓库根目录执行 `AUGMA_MICROSOFT_CLIENT_ID=<应用 UUID> ./script/build_and_run.sh --package`。打包脚本会写入 Info.plist 并注册回调 scheme；本机已保存的 Client ID 优先于构建配置。登录出现重定向地址不匹配时，核对门户中的地址是否与上述 URI 完全一致，并确认平台类型为原生公共客户端。

注册与权限参考：[注册应用](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app)、[macOS 回调配置](https://learn.microsoft.com/en-us/entra/identity-platform/scenario-desktop-app-configuration)、[Tasks.ReadWrite 权限说明](https://learn.microsoft.com/en-us/graph/permissions-reference#tasksreadwrite)。

实现依据：[Microsoft 授权码流程](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)、[创建待办](https://learn.microsoft.com/en-us/graph/api/todotasklist-post-tasks?view=graph-rest-1.0)、[列出清单](https://learn.microsoft.com/en-us/graph/api/todo-list-lists?view=graph-rest-1.0)。当前支持 Microsoft 全球服务，未配置世纪互联或美国政府云端点。

「开启到时通知」由用户主动授权，未开启也能正常计时。已授权时预先安排系统本地通知；实际展示受系统通知权限、专注模式和设备休眠状态影响。语音、通知权限不会在启动时自动请求。

## 原生设置、音频与共享场景

主窗口「设置」、App 设置窗口的「场景」页和沉浸面板使用同一个 `NativePreferencesStore`。场景外观、HUD、语言与语音反馈保存在原生 UserDefaults；没有 WebView 也能修改。已有原生保存值和之前迁移的值继续保留；新版本不再读取旧 WebView 的 localStorage。恢复场景默认仅恢复场景偏好，不清除笔记、助手密钥、监控或音频设置。原生控件仍跟随 macOS 外观，场景语言可单独选择。

「声音」由 `NativeAudioStore` 与 AVAudioEngine 本地合成原有三组和弦，支持音轨、音量、暂停 / 恢复、跳转与自然结束。音量保存在 `augma.nativeAudio.volume.v1`，已有原生音量和之前迁移的值继续保留。播放服务与视图生命周期独立，关闭窗口、切换侧栏或进出沉浸模式均不会中断；模拟设备的休眠 / 断开也不影响真实音频。系统休眠时暂停，唤醒后恢复先前播放意图，音频设备变更会重建引擎并保持进度；失败时显示可重试错误。音频回调在非主线程合成，通过原子参数接收操作，不在实时回调中访问 SwiftUI 或主线程状态。

菜单栏的播放 / 暂停、原生快捷指令与语音控制共用该音频服务；「播放声音」「暂停声音」「上一首」「下一首」以及对应英文 / 日文指令无需网页。播放时每 250 ms 更新进度，暂停后停止计时任务，进度条拖动保留手柄位置直至提交。普通浏览器仍保留原有 Web Audio 与偏好行为。

进入沉浸模式时，空间由新的 RealityKit 视图呈现同一个 `NativeSpaceStore`；扫描和模拟路线不会因视图重建而重新开始。通知列表、设备状态、助手输入与回复和当前网页同样保留。网页将同一个 WKWebView 重新挂载到悬浮层，保留历史、滚动位置与页面状态。Dock 和角落按钮可切换模块、语音、HUD、桌面穿透或退出；按 Escape 或右上角退出按钮回到主窗口。不同主窗口的空间、通知、设备、助手和网页会话各自独立；偏好、音频、地图、摄像头、记录、计时、监控与天气由 App 共享。

## 通知、设备与沉浸式网页

「通知」记录当前窗口会话的应用活动，包括模拟扫描完成、场景切换、固定锚点、路线到达和模拟设备连接变化。最多保留 100 条，仅在内存中保存，支持标记已读和清空；不读取 macOS 通知中心历史。专注计时的系统本地通知继续由独立的原生服务处理。

「设备」保留连接、待机、断开与约 0.9 秒的模拟重连，明确标注为设备模拟；显示当前 RealityKit 场景、地标、扫描、锚点、模拟路线和实际原生摄像头状态。待机或断开会取消本窗口的扫描、路线和助手任务，其他原生功能仍可使用，不影响全局音频播放。

「网页」提供原生地址栏、前进 / 后退、刷新 / 停止、页面标题、加载错误，以及「在默认浏览器中打开」。输入 HTTP(S) 网址，或输入关键词使用 Bing 搜索。默认显示原生空页面，首次导航才创建 WebKit；主窗口和沉浸模式共享同一个页面及浏览历史。沉浸模式将网页扩展到桌面可用区域，顶部保留 Augma 角落按钮和时钟，底部保留 Dock；Escape 退出沉浸模式。当前版本为单页面浏览，新窗口链接在同一页面打开；下载交给默认浏览器。

网页使用 WebKit 默认网站数据存储，Cookie 与登录状态遵循 WebKit 的持久化行为；关闭网页释放页面，关闭主窗口结束该窗口的浏览会话，不清除网站数据。网页不注入 Augma 状态、脚本消息处理器或本地资源协议，摄像头与麦克风访问当前不开放。

## 原生模拟空间

「空间」使用 RealityKit 的非 AR `ARView`，通过小型 AppKit 桥接提供明确的透视相机和鼠标交互。空中庭院采用低多边形与赛璐璐色块风格：前景保留观景平台、玻璃回廊、中央树和步道，远处是七层收拢的白色浮空城、尖塔与切面悬岩，少量浮岛和云层形成纵深。`NativeFloatingGarden.swift` 按材质合并程序生成的切面网格，无需贴图或外部模型。城市场景包含美术馆、玻璃车站、公共广场、道路和错落楼群。点击模型或编号标记可选择地标，也可通过原生列表操作；当前选择显示青色标记，固定锚点显示金色标记。

「扫描空间」是约 2 秒的模拟扫描，使用单调时钟计算 0–100% 进度，渲染扫描环、扫线与进度刻度。完成后可为所选虚拟地标固定或取消锚点；选择其他地标不会把原锚点移过去。模拟路线有 4 次手动推进，显示演示距离、进度和场景中的路线标记；选择其他地标会结束当前模拟路线。切换庭院 / 城市会重置地标、扫描、锚点、路线和视角。这里不使用摄像头、空间传感器或地理位置，不识别真实环境；虚构地标不会传给苹果地图。

每个主窗口的 `NativeDemoModel` 持有一个 `NativeSpaceStore`，主窗口与其沉浸模式共用场景、选中地标、扫描进度、锚点、模拟路线和视角。主窗口和沉浸模式分别创建渲染视图，重建几何时从共享 Store 恢复状态。拖动旋转、滚动或触控板缩放会写回同一视角；原生按钮也提供缩放与复位。庭院默认从约 1.5 米的步行视点向远处眺望，拖动转动视线，缩放限制在庭院内短距离前后移动；扩展到镜头身后的草地和两侧植被形成前景包围，远城后移并使用较淡的冷色减弱反差。场景支持明暗、背景、镜像、专注和 HUD 偏好；指针视差仅在开启「景深动效」且系统未启用「减少动态效果」时响应鼠标移动。庭院云层缓移与小岛浮动使用 RealityKit 内置动画，系统减少动态效果、窗口非活动或遮挡、隐藏背景和专注模式均会暂停；切换场景或移除视图时停止并清理。扫描使用有限任务，结束、取消、休眠或关闭窗口时停止；渲染不创建常驻动画计时器。

## 原生地图导航与摄像头

「导航」使用 MapKit 原生地图。分别输入并搜索起点和终点，从结果中选择真实地点后，可查询驾车或步行路线，查看路线线条、距离、预计时间与分步指引；也可将同一组起终点和出行方式交给「苹果地图」。本版本不自动获取当前位置，不申请定位权限，也不提供行进中的自动偏航重算或语音领航。地图加载、地点搜索与路线查询使用 Apple 服务，具体路线与预计时间依地区和路况而变化。搜索、路线、地图视角和分步列表的展开状态仅保留在应用内存中，主窗口、其他窗口和沉浸模式共享；切换视图不会清空查询或重复请求。分步指引通过原生按钮展开或收起，步骤按实际显示顺序连续编号。请求有取消、过期结果隔离、限流及超时处理。

空间内的观景平台、玻璃回廊等是虚构地标，没有真实经纬度；它们的手动路线演示留在「空间」面板，并明确标注为模拟路线，不传给苹果地图。快捷指令与语音中的「打开地图」「打开导航」「打开摄像头」可直接打开原生面板，不创建 WebView，也不会自动开启摄像头。

「摄像头」使用 AVFoundation 与 AVCaptureVideoPreviewLayer。只有主动点击「开启摄像头」才请求系统摄像头权限并启动采集；支持可用的内置、外接及连续互通相机，具体设备取决于 macOS 和连接状态。镜像开关只影响预览，JPEG 照片保持原始方向。拍照后图片先保留在内存，点击「保存照片…」并选定位置后才写入本机；不请求麦克风、不录音、不上传画面。拒绝授权、设备缺失、断开、占用或保存失败均显示相应提示，可重试或进入系统隐私设置。

同一个原生摄像头会话在主窗口与沉浸模式之间共享。短暂的窗口交接保留采集；真正离开摄像头页面、窗口隐藏或最小化、应用失活、Mac 睡眠和退出时停止。回到应用不会自动重新开启。权限用途说明提供中英日三语；自动化测试使用注入的权限和采集后端，不会实际打开摄像头。

## 系统监控与天气

监控面板提供「清理磁盘与内存」入口，包含「模拟器专项清理」。点击扫描后，通过 Xcode 的 `simctl` 读取默认设备集和系统共享运行时清单，分别显示容量估算、运行状态、最后使用时间及运行时在默认设备集中的关联设备数。设备容量使用工具报告的数据目录大小，运行时使用映像大小；不递归统计挂载卷，不重复相加运行时与挂载目录。未报告容量的项目显示未知，估算不代表承诺释放空间。缺少 Xcode、权限不足或无法识别的报告会显示原因，不会当作零占用。

设备图标复用公共 `Icons/` 模块，按真实型号优先查询系统官方图片，缺少时使用统一的设备符号；运行时显示平台标识。图标保留原色、比例和透明区域，不按用户修改过的名称猜测。新增页面的调用方式与缓存规则见[原生图标复用说明](../../docs/native-icons.md)。

默认不勾选项目。只有已关闭的设备，以及默认设备集没有关联设备、可由系统删除且默认设备集均已关闭的运行时，才可选择删除；未知状态只供查看。即使同时选择关联设备和运行时，也需先删除设备、重新扫描，再选择运行时。Xcode 预览、CI 和自定义设备集不在扫描范围内；运行时为全局资源，删除会影响其他设备集，确认时必须另外勾选已自行检查并关闭相关模拟器。未作这项确认时，执行接口也会拒绝运行时删除。「AI 建议」经确认只发送匿名编号、类别、容量和状态等摘要，不发送设备名称、UUID、路径或原始报告，并明确标记其他设备集未验证；AI 仅建议检查顺序，不改变选择或执行操作，未配置 AI 时仍可手动清理。

执行前需在原生确认面板逐项核对名称、类别和估算，并确认永久删除。设备中的 App、登录状态与测试数据会一起移除，不能从废纸篓恢复；运行时以后需要重新下载。确认绑定本次扫描及具体项目，五分钟后失效，执行前重新读取身份、状态和依赖；变化项跳过。删除仅调用固定 `simctl delete <UUID>` 或 `simctl runtime delete <UUID>`，不会批量删除全部设备、自动关闭其他模拟器或直接移除目录。运行时删除可能由系统异步完成，回执区分已删除、跳过、失败和等待系统完成，并显示同卷可用容量变化；该变化也受其他应用写入影响。扫描和 AI 可取消，关闭面板会丢弃迟到回复；已确认的删除执行期间需等待完成再关闭或退出。

内存整理复用现有应用排行与压力读数，逐个确认后请求应用正常退出；应用可以等待保存或拒绝退出，不强制终止、不清除交换文件，也不承诺回收特定字节数。请求前复核 PID、应用路径和启动时间，禁止退出 Augma 本身；可打开活动监视器进一步检查。

侧栏「系统 → 系统监控」显示真实 CPU、内存、磁盘、网络和电池读数，也可按 `⌥⌘M` 或执行「打开系统监控」「查看网速」进入。CPU 显示总占用及用户 / 系统占比；内存显示已用、物理总量、压缩内存、交换空间和压力；磁盘列出启动数据卷与本地可见卷的容量；网络显示当前物理接口的实际上下行流量；电池显示电量、供电 / 充电状态与系统提供的预计时间。无内部电池的 Mac 显示相应说明。磁盘使用文件系统容量口径，与 Finder 包含可清理空间的估算可能有差异；内存排除可回收文件缓存。

「应用内存排行」按占用降序展示当前用户运行中的桌面 / 菜单栏应用、图标、进程数与比例条，默认显示前十名，可用原生玻璃按钮展开全部；菜单栏摘要显示前三名。嵌套 Helper、包内 XPC 与可确认父子关系的外部子进程按所属应用合并，同一应用的多个实例按应用路径汇总；从其他应用启动的独立应用仍分别统计。使用公开 `proc_pid_rusage` 的 `ri_phys_footprint`，不以 RSS 替代，包含压缩等内存记账；逐进程合计不等同于系统已用内存或全系统去重 RAM。条形以首位应用为基准。无法确认归属的共享系统服务（包括父进程已脱离应用的系统 WebKit XPC）不猜测归属；不可读取的已归属进程标注为部分不可读取，数值可能低估。进程退出、PID 复用和读取失败不会沿用旧排行。采样在后台执行，沿用现有可见性与休眠策略，不请求管理员权限。原生卡片与玻璃按钮搭配 Augma 静态环形标识、青色比例条；macOS 15 使用原生材质回退。

主窗口、菜单栏摘要和 HUD 共用一个原生采集服务，不通过网页，不上传系统指标。设置窗口的「系统监控」页可选择仅手动刷新或 1 / 2 / 5 / 10 秒间隔、开关菜单栏摘要和固定 HUD。默认每 2 秒采样，磁盘每 30 秒刷新；手动刷新会重新读取磁盘。没有可见消费者时停止，休眠时暂停，恢复后重新建立 CPU / 网速基线。网络采用 64 位接口计数器，首样本、接口切换或失效基线显示不可用，不把累计流量当作当前网速；只选一个 Wi-Fi / 以太网物理接口，避免叠加 VPN 流量，暂不统计虚拟接口和 Thunderbolt Bridge。

监控详情采用自适应仪表卡片：可用宽度达到 656 pt 时以两列展示 CPU、内存、磁盘和电池，窄宽度回到单列，内容最大宽度 1040 pt。圆环与主数值位于卡片左侧，用户 / 系统占比、压缩内存、交换空间、容量和供电等细项在右侧对齐；卡片内部空间不足时纵向排列。控制区优先合并为紧凑横行，采集选项与统计说明按需展开。应用排行保留横条，网速以并排读数及可选曲线展示。布局继续读取同一份监控快照，未增加采样、计时器或历史缓存。320 / 480 / 768 / 1040 pt 的原生宿主离屏渲染及浅深色检查通过，宽布局显著减少概览高度，当前应用已验证四项指标同屏。全量 Swift 测试通过。

菜单栏、HUD 与监控详情使用 SwiftUI 原生 Gauge 搭配静态圆环，CPU、内存、磁盘与电池以实际占用 / 容量比例绘制；应用排行继续使用便于比较的横条。菜单栏显示启动数据卷占用与可用空间，详情页保留各卷读数。内存颜色由系统压力决定，不因 GB 数值或排行第一而告警；磁盘剩余空间不高于 10% 使用橙色、不高于 5% 使用红色；未接外部电源时电池不高于 20% / 10% 同样区分低电量，充电使用绿色。CPU 使用青色表示当前负载，负载高本身不判断为故障。暂停和不可用显示灰色，未知容量使用虚线环与缺失值，状态仍有文字可读。上传为蓝色、下载为青色，橙红保留给需关注的状态。圆环仅随现有快照重绘，没有额外定时器、持续动画或玻璃图层。本轮浅色 / 深色原生渲染、菜单栏 400 pt 宽度与 HUD 162 pt 高度检查通过，内存 / 磁盘 / 电池详情完成实际应用走查。

在监控面板的「采集选项」或设置的「系统监控」页，可分别开关应用内存排行、温度与风扇、网速历史曲线，并可用「启用系统监控」总开关暂停全部采集。新传感器和曲线默认关闭；已有应用排行默认开启。主窗口和菜单栏可见时按选择采集，只有 HUD 可见时跳过进程扫描、传感器与历史。仅手动刷新模式在界面首次可见时读一次，之后只响应「刷新」，没有重复定时任务；CPU 与网速仍需要相邻有效采样。所有消费者关闭、窗口隐藏 / 遮挡或休眠后，停止采样并释放排行、历史与读数缓存；下次打开从新基线采样，不连线跨越休眠与接口切换。设置页本身不触发采集。HUD 在监控与待命状态使用静态环形标识，避免为装饰持续绘制。

「温度与风扇」最快每 5 秒只读访问一次 AppleSMC，每次读取后关闭 IOKit 连接，不安装特权助手、不申请管理员权限、不控制风扇。CPU 温度使用已识别芯片的有效测点，Apple 芯片显示平均值，Intel 优先封装 / 芯片测点；排除无效及停用核心占位值。芯片键映射覆盖 Intel 与 M1–M5；AppleSMC 协议非 Apple 公开稳定接口，未知机型、系统限制或读取失败显示不可用，不以零代替。风扇正常停转显示 0 RPM，只有成功读取到风扇数为零才显示无风扇。协议与键映射参考 [Stats 的原始实现](https://github.com/exelban/stats/blob/master/SMC/smc.swift)和[传感器定义](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift)，Augma 仅实现读取。

网速曲线使用 SwiftUI Canvas 随新采样重绘，无独立动画或计时器，也不引入图表依赖。仅保留当前接口最近 120 秒、最多 120 个有效点，不写文件或上传；关闭曲线即释放历史。上传为蓝色、下载为青色，表示真实流量而非网络测速。

2026-10-26 在 Apple M5 Pro / macOS 26.6.2 上完成原生界面走查：成功读取 18 个有效 CPU 测点与两只风扇，硬件读取约 8 ms；曲线、独立开关、手动刷新和总暂停已验证。测试包含最后一个消费者关闭后超过刷新周期不再采样的检查。同次调试构建的 5 秒宿主进程采样：手动模式约 94.3 MiB / 单核 CPU 0.010%，总暂停约 90.1 MiB / 0.007%。这是整个宿主的短时观测，受界面缓存、系统压缩与机器负载影响，不能当作监控模块独占内存或长期基准；Intel、其他 Apple 芯片与 macOS 15 尚未完成真机验收。

在详情页或菜单栏勾选「固定系统监控到 HUD」后，独立窗口显示 CPU、内存、磁盘可用量、上下行速度和电量，固定内容不会让窗口始终置顶。关闭主窗口仍可使用 HUD，固定偏好会保留到下次启动；从 HUD、详情页、菜单栏或设置中取消固定都会立即隐藏窗口，「隐藏窗口」则保留固定偏好。HUD 在 macOS 26 上使用通透的 Clear Liquid Glass，macOS 15 使用超薄材质，避免整块灰白磨砂底。状态栏图标保持静态，实时读数位于弹层和 HUD 中。

主窗口「天气」使用限宽居中的紧凑概览：突出当前温度和天气图标，最高 / 最低温并入天气摘要，体感、湿度与风速横向排列。更新时间和刷新入口位于卡片右上角，悬停时间可查看天气时间和获取时间。「我的城市」使用自适应卡片，支持切换、通过卡片菜单删除及重启恢复；「添加城市」在原生弹出面板中搜索，旧版最近选择和天气缓存会自动保留。排版参考 [Clima](https://dribbble.com/shots/26240563--Clima-dashboard) 的指标分组和 [Minimal Weather Widget](https://dribbble.com/shots/25580019-Minimal-Weather-Widget-UI) 的紧凑层级，图标继续使用原生 SF Symbols。

手动选城无需定位权限；点击「使用当前位置」才请求 macOS 定位授权，获取一次大致位置，由 Apple 解析城市名，不持续跟踪。定位失败仍可手动添加城市；重新打开页面仅使用上次保存的位置，不自动重新定位。

数据来自 [Open-Meteo](https://open-meteo.com/)，无需 API Key；发送搜索词和城市坐标，定位坐标取小数点后两位。城市、最后选择和天气缓存保存在本机，切换城市优先复用各自缓存。缓存 15 分钟，每城手动刷新间隔至少 1 分钟，离线或服务错误时保留上次读数并标注时间。免费接口[仅限非商业用途](https://open-meteo.com/en/terms)，页面「数据来源」附 Open-Meteo / CC BY 4.0 / GeoNames 署名。当前值是气象模型的估计，非设备传感器温度；CPU 温度由可选的「温度与风扇」监控提供，与天气数据独立；暂未接入 GPU 温度。

Apple Weather 可通过 [WeatherKit](https://developer.apple.com/weatherkit/) 接入，需要 Apple Developer Program 会员和应用能力配置，本版本使用 Open-Meteo。沉浸模式复用同一原生天气、记录、计时、系统监控、声音、设置、地图和摄像头面板，并通过共享空间 Store 呈现 RealityKit 场景。通知、助手和设备均直接使用原生状态。

## 语音指令

主窗口的语音面板包含原生 SwiftUI 环形动效与橙青色声纹：聆听时使用麦克风 RMS 音量驱动，等待权限、识别及助手处理时显示处理中动效。音量在音频回调中限频到每秒约 20 次，经平滑后直接交给原生小视图，不经过网页、不保留音频副本。待命与非活动状态停止语音时间动画，隐藏的辅助 HUD 也停止环形动画，开启系统「减少动态效果」后改用静态图形和音量进度条。面板中的「预览语音动效」可切换待命、聆听、处理状态并调整示例音量，不会使用麦克风。

在主窗口侧栏打开「语音指令」，点击「开始语音识别」，说出指令后点击「结束并执行」；也可直接输入文字并点击「执行」。主窗口工具栏和菜单栏麦克风打开原生快捷指令窗并开始录音。沉浸模式左上角麦克风打开原生语音助手面板，点击开始后才录音；右上系统菜单还可打开快捷指令。也可在 App 内按 `⌥⌘V`（「语音」菜单）打开指令面板并开始录音，再按一次结束并执行；等待权限或识别结果时再次按下会取消。默认不用 `⇧⌘V`，因为 Paste、Pastebot 等剪贴板工具把它注册为全局快捷键，按下后 Augma 收不到。要换成其他按键，可在「系统设置 → 键盘 → 键盘快捷键 → App 快捷键」中为 Augma 添加菜单标题「开始或结束语音指令」（English 界面为 “Start or Finish Voice Command”，日本語界面为「音声コマンドを開始／終了」）；演示界面的快捷键列表和指令面板会显示菜单当前的按键。首次使用时，macOS 会请求麦克风和语音识别权限。语音识别由系统 Speech 框架完成，识别语言跟随演示界面当前的语言（简体中文、English 或日本語）：设备支持该语言的离线识别时优先在设备上处理，否则可能使用 Apple 在线识别服务。日常快捷指令窗与沉浸模式的原生快捷指令面板一次录音最多约 60 秒，单独的演示语音面板仍为约 12 秒；切换到其他 App 或关闭指令窗会停止录音。日常面板识别语言跟随 App 语言，演示面板跟随演示语言。

日常指令之外，演示语音面板还支持打开地图、扫描空间、播放或暂停声音、显示或隐藏 HUD、打开天气 / 通知 / 设置 / 摄像头 / 网页面板、切换深色或浅色视界，以及对当前选中地点开始模拟导航、前进一步、结束导航。语音不会自行开启摄像头。识别文字会显示在面板中；也可以手动输入指令或点击示例按钮，不需要麦克风。在浏览器中打开的网页演示改用浏览器自带的语音识别，点击开始后才请求麦克风权限。执行后会用 原生 AVSpeechSynthesizer朗读结果或助手的回复，可在演示设置中关闭「语音播报」；开始录音时会先停止朗读，避免被麦克风收进去。

## 多语言

原生菜单、设置窗口和权限说明提供简体中文、English 与日本語，跟随 macOS 的首选语言，也可在「系统设置 → 通用 → 语言与地区 → 应用」中为 Augma 单独指定。字符串表位于 `apps/mac/Localization/*.lproj`，以 Swift 源码中的简体中文原文为键，由 `script/build_and_run.sh` 复制进 App 包。用户在场景设置中另选的语言保存在原生偏好中，空间文字与助手识别使用该语言。普通浏览器仍自行保存网页语言。原生功能直接使用本地化字符串。

日常快捷指令始终只在本机匹配。演示助手也先匹配本地指令；文字输入与系统语音识别的最终文字共用同一入口。未匹配的问题才会交给明确启用的 AI 运行时。本地指令、记录和计时不依赖模型可用性。

### DSH / Magpie 助手

新配置默认选择 **DSH / Magpie**，默认不开启发送。已保存过 DeepSeek 开关的安装（包括显式关闭）继续保留该选择，钥匙串条目不会迁移或删除。

1. 自行安装可用的 **DeepSeek Harness 0.2.0-rc.2**，在 Magpie 中完成登录、模型来源和路由配置，并启动本地网关。网关联调覆盖 Magpie 0.1.1293；应用列表和推理强度管理通过官方 Magpie 0.1.1673 的独立插件验证。
2. 打开「设置 → 助手」，选择 DSH / Magpie。路径留空会检测已安装的运行时，也可填写完整可执行文件路径。macOS 桌面版的入口为 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`。旧的 `~/.local/bin/dsh` 可能只是失效 shim；仅能找到命令不代表能运行。
3. 点击「检测连接与模型」，选择 DSH 会话实际公布的模型和推理选项。模型标签显示路由 ID；切换模型后重新检测推理选项。首版仅开放 Magpie 路由，不继承 DSH 桌面端的其他 provider 或工具配置。
4. 点击「测试模型与只读工具」。这会发送一次模型请求，并让模型读取真实系统摘要、应用名称和占用，可能消耗所选模型额度。两项工具均成功后，单独打开「启用 DSH 助手」。修改路径、模型或推理选项会清除测试状态，需要重新测试。

Augma 通过 ACP over stdio 启动自己拥有的 DSH 无界面进程，不打开 DSH 桌面窗口、不自动安装或升级。DSH 管理模型上下文、工具循环与压缩。Augma 只传当前任务，不把用于显示的最近四轮记录重放给 DSH；首版显示消息级进度与工具状态，不提供逐 token 输出。每个窗口有独立会话，共享一条进程连接。闲置 60 秒释放连接；下次任务可恢复本次 App 运行期间的空闲会话。取消、关闭窗口或更改配置结束旧任务，下一次取消后任务使用新会话。App 重启后不自动恢复旧聊天窗口或会话映射。

原生工具仅包括 `system_summary`、`application_usage` 与 `open_panel`。前两项读取内存压力、交换空间、磁盘容量和最多十个应用名称、近似占用及读取完整性；不读取文件内容、路径、网页标签或进程命令行。打开面板只作用于当前窗口，不开启摄像头、不导航网址。模型没有任意 shell、文件写入、结束应用、删除文件或清理命令工具。

Augma 使用专属运行 profile 和 `~/Library/Application Support/Augma/Assistant/Sessions` 保存 DSH 会话；不修改 DSH 全局/桌面 profile，不复制 Magpie 登录凭据。Magpie 的本地 `magpie-augma` 标记用于应用用量归属，不是订阅密钥。会话文件可能包含已发送的问题、工具结果和回答，留在本机；此版本没有自动保留期限或跨 App 重启的聊天历史浏览器。关闭 Augma 会回收其子进程，不结束用户原本运行的 DSH 或 Magpie。

安装 [Augma Magpie 插件](../../integrations/magpie/README.md) 后，官方 Magpie 的应用列表会显示 Augma；卡片中选择模型或路由组，页面底部或独立 Augma 插件页保存推理强度，无需修改 Magpie 源码。Augma 导出不含凭据的 `~/Library/Application Support/Augma/Assistant/magpie.json`，并在受管理时读取插件自己的推理强度设置。返回 Augma 或检测连接时同步新选择，变更会取消旧请求并清除测试状态，需要重新测试和启用。断开管理恢复接入前的配置。当前已验证 `group/augma` → GPT-6.1 Terra / Medium，继续复用本机 DSH。

检测失败会区分运行时缺失、入口失效、未验证版本、Magpie 未运行、无模型及模型不可用。请求失败提供鉴权、额度、超时或通用任务错误；不展示可能含私密内容的 provider 原始错误，也不静默改用另一条付费路由。当前仅固定验证 DSH 0.2.0-rc.2，其他版本会被拒绝，需先更新兼容验证。

### DeepSeek API 兼容入口

选择「DeepSeek API（兼容）」后继续使用原有开关与 macOS 钥匙串密钥。未匹配指令及最多四轮对话发送至 [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)；白名单回复仍由原生服务校验。浏览网页不能访问密钥或原生状态。没有启用此后端时不会因为 DSH 失败而调用它。旧客户端、语音最终事件和本地命令均有回归测试。

## 原生界面验证

`pnpm mac:verify` 构建并启动 `.app` 后检查主窗口；`swift test --package-path apps/mac` 检查原生服务、快捷键、共享状态、音量采样与菜单会话路由。其中持久化测试使用独占临时目录，覆盖重启、连续输入、计时暂停恢复、睡眠/时钟校准、编辑冲突、写入失败重试和损坏恢复。空间测试使用注入的单调时钟，覆盖扫描完成与取消、锚点所属地标、模拟路线、视角边界及窗口间状态隔离；不测试或声称真实环境扫描。地图测试注入客户端，覆盖搜索、路线失效、取消与过期结果、地图交接参数，以及后台路线回调；摄像头测试注入权限和采集后端，覆盖显式授权、取消、窗口交接、设备断开、拍照和保存错误，不打开实际设备。语音指令测试注入识别事件，音量测试使用合成 PCM 数据，不打开麦克风。浏览会话测试验证地址解析、脚本隔离和宿主切换；助手测试验证有限历史、白名单、取消和迟到回复。独立 AR 网页的测试继续覆盖浏览器端行为。摄像头、麦克风权限与真实设备能力仍需在目标 Mac 上验证。

## 应用街区

在「空间 → 应用街区」中，点击「添加应用…」选择 VS Code、Chrome 等已安装 macOS 应用，支持一次选择多个；空白街区提供常用已安装应用的快捷入口。RealityKit 大楼显示应用图标和名称，点击大楼或列表中的打开按钮启动应用或切换至已有应用。运行中、当前前台、未运行和缺失状态来自 NSWorkspace 系统事件；不读取项目文件或浏览器标签页。沉浸模式中打开应用成功后会隐藏助手，重新唤起保留当前场景。

街区有 12 个地块，可自定义名称、固定位置、交换位置、移除和撤销上一次移除，也可重新排列未固定大楼。固定的大楼不会被其他大楼挤动；移除入口不会卸载应用。布局保存在 `~/Library/Application Support/Augma/application-district.json`，主窗口、多个窗口和沉浸模式共用应用级布局及运行状态。保存失败可重试，损坏文件仅在用户选择重建时备份后替换。

应用身份使用 bundle ID，重新选择同一应用会更新路径并保留布局；原路径失效时通过系统查找相同标识的应用。应用丢失或启动失败会保留大楼并提示，不会跳到同名的其他应用。布局和运行状态测试使用可注入客户端，文件测试在独占临时目录中验证原子保存、重启恢复和损坏保护，不启动真实应用。

选中大楼后可在「应用管理 → 在 Craft Hub 查看卸载指引」跳转到软件中心。需要支持卸载指引入口的 Craft Hub；未安装或无法打开时显示错误，应用街区仍可独立使用。跳转仅通过 `craft-hub://software?v=1&bundleId=…`（或原生候选版协议）传递应用标识，不需要 Agent 连接，不传递应用路径，也不执行卸载或清理。Craft Hub 负责展示同一标识对应的本机副本、卸载程序候选及说明来源；候选只提供 Finder 定位。

## 项目区域

在「空间 → 项目区域」添加项目文件夹，绑定本机 VS Code、Google Chrome 和工作网址。最多保存 6 个区域，每个区域最多 10 个 HTTP(S) 网址，支持 localhost。点击三维区域查看入口；点击「打开工作区」保存当前配置并在 VS Code 新窗口打开项目，然后在 Chrome 打开网址。每项显示打开结果，部分失败可只重试失败项，取消会停止后续请求。浏览器接受请求后显示「已打开」，页面加载结果由浏览器显示。

配置、编辑草稿和打开结果在主窗口与沉浸模式之间共享；配置写入 `~/Library/Application Support/Augma/project-regions.json`，重启后恢复。文件夹使用系统书签，失效时可重新绑定。保存失败可以重试，无法读取的配置不会自动覆盖。项目区域支持命名、位置交换、移除和撤销，移除不会删除项目文件。打开成功会收起沉浸助手，有失败项则保留结果。

VS Code 使用绑定安装包中的 CLI 和独立路径参数，不要求安装终端 `code` 命令；Chrome 使用 NSWorkspace。原生测试使用注入客户端验证批量打开、部分失败、重复点击、取消、迟到结果和共享草稿，真实临时目录验证书签与持久化，不启动外部应用。

[空间工作区方案](docs/workspace-world.md)记录了应用大楼、项目区域，以及后续 AI 场景生成设计。当前只打开已绑定的项目和网址，尚未接入 AI 三维生成，也未同步 VS Code 当前项目或 Chrome 当前标签。

### 可选连接 Craft Hub

在 Craft Hub 的「设置 → Agent 连接」选择共享项目并启用只读访问，复制 **MCP · JSON**。在 Augma 的「空间 → 项目区域」选择「从 Craft Hub 添加…」，或在已有区域选择「绑定 Craft Hub 项目…」，粘贴配置、选择项目并确认。无需启用插件读取，也不需要在 Augma 中安装 Node 或运行 MCP 命令。

连接后，区域名称、项目目录、信任状态及命令／技能摘要来自 Craft Hub；应用选择、工作网址和三维布局由 Augma 保留。摘要最多展示前八项能力，并显示完整命令／技能数量。「在 Craft Hub 中查看」使用项目的 Git 引用导航；没有 Git 引用时打开 Craft Hub 首页。打开工作区前会重新读取项目资料，随后仅打开编辑器与已保存网址，不执行项目命令或授予信任。

连接失败、授权撤销或项目移除时保留区域，显示需要重新连接或更换绑定的原因，不自动使用过期目录。「解除绑定，使用本地配置」恢复原来的区域名称和文件夹，应用、网址和布局保持不变。独立添加的区域不依赖 Craft Hub。不同配置源中的同名或同 ID 项目不会自动替换绑定。

连接保存于 `~/Library/Application Support/Augma/craft-hub-connection.json`，只包含本机地址和授权文件路径，不保存令牌。令牌由 Craft Hub 管理，每次读取时使用当前凭据；项目资料只缓存在本次会话中。Craft Hub 关闭后连接不可用；端口变化时重新粘贴当前配置，同一凭据来源的区域绑定会保留。Augma 断开连接不影响其他客户端；要撤销所有使用该授权的客户端，请在 Craft Hub 撤销连接。

项目区域文件升级为 v2，兼容读取 v1 的独立项目；旧版 Augma 会拒绝覆写 v2。自动化验证：`swift test --package-path apps/mac`。跨仓库真实宿主验证：`node script/verify-craft-hub.mjs /absolute/path/to/craft-hub`，需该仓库已安装依赖；脚本使用独立临时数据、原生宿主门禁和真实 Swift HTTP 客户端，结束时撤销测试授权、关闭宿主并验证进程退出。
