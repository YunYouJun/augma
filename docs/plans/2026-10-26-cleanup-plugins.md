# 可选清理引擎与 AI 清理

日期：2026-10-26。状态：首版应用市场、Mole CLI 安装、自然语言目标计划、可选 AI 调整及原生确认执行已实现。Mole 广泛清理、Purge、外部 MCP 和完整插件生命周期仍为后续设计；现有原生清理和 Homebrew 专项流程继续可用。

## 首版交付范围

- 原生「应用市场」提供 Mole CLI 单一可信目录项，经 Homebrew 官方 `homebrew/core/mole` 安装。已实际从 Augma 点击安装 1.64.0，验证安装状态、版本及真实 JSON 扫描。未知正式版本或 Homebrew 环境覆盖配置不会自动安装，已有 CLI 不自动升级。
- 市场、原生助手与快捷指令共用 `ApplicationMarketStore.requestCleanup`，支持「帮我尽量腾出 20 GB，保留模型和最近项目。」；笔记和待办优先捕获，不执行其中嵌入的命令。无 AI 配置也可生成本地计划。
- Mole 只提供只读占用分析，逐项保留 `scan_status`，未完整读取不显示成空目录。分析有 45 秒和 4 MiB 上限；实际大用户目录扫描耗时超限，已补充失败提示、本地计划回退及缩小目录入口，不通过延长无限扫描解决。
- 执行仍由已有原生白名单扫描器负责：模型目录和项目源码不进入执行范围，最近项目暂保留全部 DerivedData；目标计划仅允许旧安装包并过滤模型相关名称。其他 Mole 占用行仅可在 Finder 查看。不会调用 `mo clean`、`purge`、`optimize` 或清空废纸篓，不修改 Mole 全局白名单。
- 目标、候选估算与缺口由本地计算，GB 按十进制显示。AI 复用所选 DSH / DeepSeek 运行时，经确认仅接收匿名数字摘要，可调整最多 12 个已有候选，不能产生路径、命令、批准或额外删除。AI 调整后原计划 ID 作废，默认仍不勾选。
- 勾选具体候选后确认一次；执行前复查 ID、目录、5 分钟有效期及文件元数据。回执显示移入废纸篓、跳过、失败和前后可用容量；不把移入废纸篓视为已释放空间。临时 fixture 已验证确认边界、元数据变化、部分失败、重复执行、取消与迟到 AI 结果。市场不创建后台轮询。

代码与用法见 [macOS README](../../apps/mac/README.md#应用市场与目标清理)。下文是更完整的后续设计，未声明已实现的能力不作为首版承诺。

验证记录：相关 Swift 测试 78 项通过，1 项跳过（本轮未重复运行 Homebrew 只读预览），包含真实已安装 Mole 的临时目录只读扫描。原生界面已验证安装、一句话路由、大目录超时回退、选择下载目录后成功显示只读占用明细。中英日字符串通过 `plutil`；明暗、窄宽布局已渲染检查。本轮未调用真实模型优化；已通过注入 completion 验证匿名请求、严格候选 ID、不能自行勾选或执行、取消和迟到响应。此次没有执行新的用户文件清理。

目标：用户可以按需安装或启用清理引擎，Augma 提供统一的原生界面与 AI 工具调用。未安装外部引擎时不下载、不启动后台进程，基础清理仍可独立使用。

## 选择与事实依据

这里的 Purge 指独立项目 `jithin-sabu/purge-app`，不是 Mole 中的 `mo purge` 子命令。

| 维度 | Mole CLI | Purge |
| --- | --- | --- |
| 官方提供形态 | 免费开源 CLI；收费原生桌面应用另行提供 | 免费原生 Mac 应用，MIT 源码 |
| 已公开的机器调用能力 | `mo analyze --json`、清理 dry-run、`mo history --json`；部分能力仍是文本或交互流程 | 官方 README 未找到可直接使用的稳定 CLI/JSON/MCP 契约，不能把安装 GUI 视为可供 AI 调用 |
| 作为可选后端 | 优先评估现有 CLI，按固定版本验证和声明能力 | 需要先审阅和抽取适用的原生实现，制作 Augma 自有适配实现；或先只提供打开应用 |
| 源码复用 | GPL-3.0，代码移植、链接与分发需分别核实 | MIT，适用代码可在保留许可和署名后按模块复用，仍需审计依赖和行为 |
| 优先级 | 以 AI 调用和可选安装为目标时优先 | 以原生源码复用和更细粒度控制为目标时优先 |

来源：[Mole 官方说明](https://github.com/tw93/Mole)、[Mole CLI 与桌面应用区别](https://mole.fit/#faq)、[Purge 官方说明](https://github.com/jithin-sabu/purge-app)、[Purge MIT 许可](https://github.com/jithin-sabu/purge-app/blob/main/LICENSE)。这是接入可行性判断，不是两款工具清理效果或安全性的实机排名。

Mole 的目录分析 JSON 会标注 `complete`、`partial`、`unavailable`，不能把进程成功退出等同于完整扫描。其部分预览和执行能力不是逐文件 JSON 事务。`mo clean` 默认会处理用户废纸篓，不能直接作为 Augma 默认动作；在验证如何满足本次计划的保护范围之前，该动作只开放预览。来源：[Mole Analyze / Safety / Clean](https://github.com/tw93/Mole#safety)。

## 首版形态：轻量引擎目录

先提供内置适配器目录，不开发任意脚本插件市场：

- **Augma 原生**：现有安装包、DerivedData 与 Homebrew 专项能力，不依赖 Mole 或 Purge。
- **Mole CLI（可选）**：检测已安装版本，展示支持能力；用户主动选择安装时才通过官方来源安装。已安装但不兼容时显示原因并限制能力。
- **Purge 原生扩展（后续）**：尚未形成稳定工具接口前，不显示成“安装后即可 AI 清理”。若只安装外部 GUI，能力明确为打开应用；若后续从 MIT 代码形成 Augma helper，说明它是 Augma 适配实现，不冒充上游官方插件。

每个目录条目显示中文名称、用途、来源、许可、兼容版本、安装大小估计与实际能力。状态区分未安装、安装中、可用、能力受限、版本不兼容和失败；失败提供重试与诊断。

可以同时安装多个引擎，每次计划选择一个主要引擎。对原生专项与外部引擎发现的重叠对象进行本地去重，避免重复计数或重复执行。

外部可执行文件按需启动，用完释放。适配器停用时取消只读工作；执行中的清理需先结束并产生回执。卸载仅移除 Augma 自己安装且可证明归属的内容，不删除用户原有 CLI、配置、历史或共享依赖。

## 同一 interface 支持界面与 AI

将 variation 放在 `CleanupEngine` seam，各 adapter 隐藏原生文件处理、外部进程、输出解析、版本检查和取消的 implementation：

```text
capabilities                         已检测的能力和限制
scan(scope) -> ScanReport             在用户指定或已授权范围内读取
prepare(scanID, selection) -> Plan    形成可审阅的具体计划
run(approvedPlanID) -> Receipt        复查并执行已确认的计划
```

取消与超时沿用任务生命周期；回执直接作为结果返回，避免调用方轮询。界面和 AI 跨同一个 seam，不能各自拼装清理命令。

能力声明至少区分：只读扫描、结构化结果、预览、对象级执行、来源整体执行、可恢复动作与永久动作。未知版本、无法解析输出或缺少受限执行能力时降级，不通过模拟点击第三方 GUI 补成无人值守执行。

插件目录和安装是另一个 module，负责可信来源、固定版本、校验、升级与移除。引擎不能修改主应用的许可，也不能声明自己有超出 macOS 授权的能力。通过外部进程调用不自动免除再分发义务；首版优先调用用户已安装或用户主动安装的外部 CLI，不把 GPL 源码编入主应用，具体分发安排另行核实。

## AI 清理的含义与流程

“AI 清理”指理解目标并使用清理工具，不仅是清理 AI 软件的缓存。原生界面与 AI 都基于以下流程：

1. 理解目标，例如“尽量腾出 20 GB，保留模型和最近项目”；目标、排除项和可访问目录由本地记录。
2. 查看已安装引擎的实际能力；未安装的可选项由用户决定是否安装，AI 不能把目录条目当作安装授权。
3. 调用只读扫描，结合完整性、重建成本和已知保护规则生成计划。达不到目标时报告缺口，不编造可释放量。
4. 由原生界面展示具体对象或来源级范围、估算与后果，一批计划确认一次；不同后果不能合并成含糊的“全部优化”。
5. 执行前复查版本、身份、范围和有效期，执行后展示成功、跳过、失败以及同卷空间变化。

AI 暴露的工具可对应 `cleanup.scan`、`cleanup.plan`、`cleanup.execute`。执行批准由本地 UI 产生，并绑定计划、引擎版本、扫描版本及范围；模型不能自行生成批准。计划或执行范围发生实质变化时原批准失效。

扫描结果中的路径与文件名属于数据，不作为模型指令。联网模型默认只接收已审阅的类别、匿名候选 ID、容量、完整性与规则说明；原始工具报告、文件内容和凭据不外发。现有 DeepSeek 配置、取消和迟到结果丢弃机制继续复用。

首版先支持 Augma 内置 AI。Mole 官方的 Agent skill/plugin 不会自动变成 Augma 的模型能力，仍需实现本地工具路由。未来如需供 Codex 等外部 Agent 使用，再将同一个 interface 暴露为本地 MCP，复用相同确认与回执，不另写清理实现。当前不因这个需求新增 AI SDK。

## 交付顺序与验收

### P1：引擎目录、Mole 只读接入和 AI 计划

- [x] 复用现有能力建立轻量目录、版本检测与能力声明；基本原生流程不依赖外部安装。
- [x] 固定 Mole 1.64.0，验证实际安装、JSON、扫描完整性和退出码；清理预览与广泛执行未接入。
- [x] 完成未安装/不兼容/失败/权限不足的原生状态；安装仅由明确动作触发，使用 Homebrew 官方 formula。
- [x] 自然语言目标能调用扫描和计划，显示保护项、估算与缺口；AI 可基于匿名摘要调整，未实现的执行能力不宣称可用。

### P2：AI 驱动的确认、执行与核对

- [ ] 先把现有原生与 Homebrew 的执行接到同一个 interface，覆盖界面和 AI 两个调用方。
- [ ] 逐个验证外部引擎动作的范围、废纸篓行为、永久移除、配置覆盖和交互要求，满足能力契约后才开放。
- [ ] 覆盖计划过期、确认后变化、取消、部分失败、重复执行与真实空间变化；先用临时目录和假执行器验证，再由用户选择真实候选验收。
- [ ] 一次批准对应一个具体计划，AI 不能借此安装其他软件、扩大目录或执行额外删除。

### P3：Purge 原生扩展与外部 Agent

- [ ] 审阅 Purge 扫描/保护规则的源码与许可，验证能否独立抽出适用模块，保留许可与来源记录。
- [ ] 如需独立 helper，定义并测试结构化请求/结果、取消与生命周期；GUI 本身只提供启动能力时如实标注。
- [ ] 同一批 fixture 对比 native / Mole / Purge 适配结果、重叠计数、性能和无任务时的资源占用。
- [ ] 确有外部 Agent 使用需求时再接本地 MCP，复用同一 interface，不引入第二份执行逻辑。

验收重点：用户可以不安装任何可选引擎使用已有清理；选择安装后得到明确的新增能力；AI 能完成“理解目标 → 扫描 → 计划 → 确认 → 执行 → 核对”，而不是只返回建议文本或打开一个外部窗口。整个过程可见、可取消，任务结束后不留常驻扫描或轮询。
