# Augma DSH 默认运行时接入 Goal

日期：2026-10-26。跟踪 Issue：[YunYouJun/augma#9](https://github.com/YunYouJun/augma/issues/9)。

本文是实施计划与完成记录。2026-10-26 已完成首版实现和约定范围的验证；逐项证据、真实联调与夹具的区别、硬件和辅助功能验收边界见[验证记录](./2026-10-26-dsh-runtime-validation.md)。

## Goal objective

为 Augma macOS 交付可用的 DSH 默认 AI 运行时：通过经过版本验证的 ACP 无界面进程管理模型会话，复用 DSH 的 agent 循环与上下文能力，并验证经 Magpie 使用用户已配置模型的链路；将 Augma 原生工具、文字和语音助手及系统清理 AI 建议接入统一运行时边界。保留既有配置与确定性本地功能，完成协议、生命周期、迁移、业务边界测试、真实 macOS App 验收和性能记录，更新 Issue #9 与使用文档，交付可审阅的实现和明确的验收证据。

在新会话中使用此 objective 创建 Goal，不设置 token budget。持续推进到下面的完成条件全部满足；没有实际验证的项目不得勾选或据此宣布完成。

## 已确定的产品与技术决策

1. DSH 是默认 AI 运行时；首版优先使用 ACP over stdio。模型循环、上下文压缩及模型会话由 DSH 持有。
2. Augma 保持原生 SwiftUI，负责输入、展示、工具、业务状态、取消和必要确认。不嵌入 DSH 桌面界面。
3. 模型目标链路为 Augma → ACP → DSH → Magpie → 模型。首版固定验证并开放 Magpie provider；其他 DSH provider 留待独立兼容验证，不静默改用其他付费路由。
4. 新配置默认 DSH；升级保留已有 DeepSeek 开关、钥匙串条目和显式选择，测试并切换后端后才使用新路由。
5. 打开面板、记录、计时等确定性本地指令沿用原生服务；AI 不可用不会阻断这些功能。
6. 首版复用已有本机 DSH，不自动安装、升级或捆绑运行时；依赖缺失应准确提示。Magpie 仍负责自己的登录、订阅和路由配置。
7. 不引入 AI SDK，不自行建设通用 harness、流程编排引擎或插件市场。标准协议优先复用合适的 SDK，采用前核实版本、许可证、平台和能力。
8. ACP 只能按实际公布能力使用。当前上游文档中的自动化接口不提供原始 provider token 增量、历史重放和部分专属交互；首版可以显示消息级输出与工具状态。
9. 若固定版本的 ACP 存在首版必需能力缺口，先记录最小复现与影响，再评估 DSH 官方 SDK；保留 DSH 默认运行时，首版只维护一种传输实现。涉及产品范围改变时同步 Issue 说明，不重开泛化选型。

## 开工与共享工作区约定

- 先读取适用的 AGENTS.md、Issue #9、本文、apps/mac/README.md、package.json 和相关源码。实际构建、调试、界面验收按相应 macOS 技能执行。
- 本计划创建时，主检出位于 main，已有多项未提交的原生 UI、清理、配置和发布改动，并有其他 Augma 会话活动。开工重新读取 git status/diff 和相关会话状态，不把这些改动归属于本 Goal。
- 记录 HEAD、初始改动清单及将修改文件的基线；不能 reset、clean、stash、切换分支或覆盖这些既有改动。优先新增独立模块，在修改共享入口前重读最新内容并做增量集成。
- 未获得额外请求时使用当前项目的本地环境，不替用户切换其他会话或创建更多执行会话。出现同文件并行写入时，先推进独立工作，再处理确实冲突的集成点。
- 提交信息遵守 Conventional Commits；只提交能明确归属本 Goal 的改动，不能整包提交脏工作区。归属不清的部分保留为审阅 diff，不强行提交。
- 不将 token、cookie、私钥、证书或 session 文件写入源码、Issue、日志或测试夹具。DSH 自己读取其凭据，Augma 不复制凭据内容。

## P1：运行时与会话

- [x] 从具体 DeepSeek 客户端抽出精简的原生运行时边界，覆盖提交、事件、工具状态、权限、取消、结束和错误；保留兼容客户端的能力。
- [x] 实现或复用 Swift ACP 客户端，以独立 argv 启动 DSH 无界面进程。处理消息分帧、请求关联、双向请求、乱序响应、断开、错误与输出上限，不使用 shell 拼接用户输入。
- [x] 按需启动并复用连接；区分连接失败、协议错误、任务错误和用户取消；stdout 专用于协议，stderr 日志限量并脱敏。
- [x] 明确窗口、业务场景与 DSH session 的映射。DSH 持有模型上下文，展示记录只用于 UI，不额外拼接一套四轮历史回放给 DSH。
- [x] 模型切换、窗口关闭、睡眠及取消时终结旧请求和待确认状态，防止迟到事件更新新任务或执行过期工具。
- [x] 支持能力允许的恢复；恢复写操作前查询真实业务状态，禁止自动重放副作用。退出 App 后回收属于 Augma 的进程，不结束用户原有 DSH/Magpie 进程。

阶段出口：协议与生命周期测试通过，能以真实 DSH 完成最小任务及取消，不需要启动其桌面窗口。

## P2：原生工具与业务接入

- [x] 建立受限 MCP 工具桥，首批提供系统摘要、应用占用查询、打开面板等已有原生能力。优先评估官方 MCP Swift SDK。
- [x] 工具有明确参数/结果 schema、窗口或业务会话范围、超时和可用条件；由原生服务返回真实数据与错误。
- [x] 使用 Augma 专用配置限制挂载能力，验证模型没有因此获得任意 shell、文件写入或其他应用访问能力；没有已支持的隔离方式时不能默默沿用宽权限默认值。
- [x] 将 ACP 权限请求接到原生确认，正确返回拒绝和取消。已有待办/清理等业务确认与防重复机制继续有效，不添加无关确认流程。
- [x] 将 NativeAssistantStore 的文字与语音接入统一运行时；本地解析先行，AI 答复和工具结果分别处理，播报不伪称操作成功。
- [x] 系统清理 AI 建议使用同一运行时边界，但仍只发送有限摘要并校验结构化结果。扫描、候选、选择、清理确认及执行由现有原生服务负责。
- [x] 与正在进行的清理/界面工作兼容，只调整 AI 依赖入口，不顺带重写其扫描、清理与布局模块。

阶段出口：真实数据能进入任务，工具结果能返回 DSH；拒绝、取消和失败不产生副作用；已有本地功能不依赖模型可用性。

## P3：配置、迁移与原生体验

- [x] 将现有 DeepSeek 专属配置页整理为 AI 助手设置，提供运行时、DSH 路径/配置、连接状态、可选模型、推理选项与测试入口。
- [x] 模型选择来自所选 DSH 会话实际公布的能力；订阅登录与模型来源管理留在 DSH/Magpie，不硬编码完整厂商模型列表。
- [x] 新配置默认 DSH；读取并保留旧偏好与钥匙串条目，显式切换后端。测试连接不能提前启用其他业务的数据发送。
- [x] 提供运行时缺失、协议不兼容、Magpie 未启动、模型/额度/鉴权错误和可重试状态；不静默切换 provider。
- [x] 为普通窗口、菜单栏和沉浸入口复用同一连接/业务状态，避免每个视图自行启动进程。
- [x] 更新中英日文案，验证键盘、VoiceOver 使用的 AX 树、窄宽度、浅深色、长路径和长错误文本（未启动 VoiceOver 实际播报）。遵循现有原生布局与系统外观。

阶段出口：用户可在设置中完成检测、选择模型、测试和启用，已有配置升级及不可用场景行为明确。

## P4：验证、证据与交付

| 验收场景 | 通过条件 |
| --- | --- |
| 无 DSH / 无 Magpie / 无凭据 | 状态准确，本地指令可用，不自动安装或切换付费路由 |
| 真实模型与工具循环 | 读取内存压力 → 查看应用占用 → 根据真实结果给建议；步骤由 DSH 决定 |
| 权限与业务操作 | 拒绝不执行，必要确认保留；写操作不会因重试或恢复重复发生 |
| 取消与迟到事件 | 停止旧任务，旧回复和工具请求不能作用于新任务 |
| 多窗口与进程异常 | 不串线，崩溃可恢复，退出后无属于 Augma 的遗留进程 |
| 会话恢复 | UI 记录和 DSH 上下文分别恢复，不假设 ACP 提供历史重放 |
| 旧配置与现有功能 | DeepSeek 显式配置、本地指令、语音与清理建议均有回归证据 |
| 原生设置与入口 | 实际 App 完成配置和使用；中英日、键盘和辅助功能可用 |
| 性能 | 记录环境、冷启动、首个反馈、任务耗时、忙碌/闲置 CPU 与内存；无请求时不轮询 |

- [x] 协议夹具和业务测试覆盖消息分片、异常输出、取消、权限、会话映射、配置迁移与结构化结果边界。破坏性测试只用临时对象或注入执行器。
- [x] 运行受影响测试，再运行相关 Swift 测试集及项目要求的检查。记录原有失败，避免修复无关问题。
- [x] 使用仓库实际构建脚本与签名约定完成 macOS 构建和真实 App 走查。不要猜测普通 swift test 能替代项目所需链接参数。
- [x] 实机验收默认只读，不用真实用户文件或清理动作验证副作用。若具体写操作确实需要额外授权，先完成可审阅的预览与其他验证，再说明所需动作。
- [x] 更新 apps/mac/README.md、验证记录和本计划；只把有证据的项目标为完成，并同步 Issue #9 的有效进度。
- [x] 输出实现摘要、可审阅 diff/提交、检查结果、真实联调与 UI 证据、性能读数，以及尚未验证的外部条件。未经请求不合并、发布或改动其他会话。

## Goal 完成条件

1. DSH 默认运行时与选定传输实际可用，Magpie 真实模型链路及工具往返有证据。
2. 文字、语音和清理建议已接到同一运行时边界，确定性本地功能与既有配置保持可用。
3. 权限、取消、恢复、进程管理、配置迁移及模型输出校验通过适当测试和原生 App 验收。
4. 已记录性能、依赖版本、兼容限制与使用说明，Issue #9 的清单与证据一致。
5. 本 Goal 的代码可独立审阅，既有及并行工作未被覆盖；没有把仅通过模拟的行为宣称为真实联调成功。

缺少登录、配额或可运行依赖时，继续完成其他独立工作，明确记录剩余验收项；不能因此把整个 Goal 标为完成。Goal 的状态变更遵守工具本身的规则。
