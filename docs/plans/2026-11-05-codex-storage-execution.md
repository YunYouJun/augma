# Codex 缓存与日志清理执行

在 Augma 原生系统清理中扩展已有预览，不在 Craft Hub 重复实现。范围仍仅为已知缓存叶子和旧诊断日志。会话、历史数据库、工作树、生成成果、凭据及其他持久状态继续排除。Mole 始终仅作可选只读复核。

## 用户流程

按需分析 → 默认零选择 → 逐项勾选 → 重新核对生成预览 → 审阅列出完整范围与每个文件的确认页 → 明确确认移入废纸篓 → 逐项结果回执。返回确认页不执行任何操作。清理前需退出 Codex 桌面应用与 CLI；Augma 不代为退出其他应用。

只移动明确选中的普通文件，不递归删除目录、不清空废纸篓。逻辑大小单独标注，不声称等于净释放量。用户可以从废纸篓恢复；本版不提供自动撤销或自动重试。

## 执行约束

- 独立 Codex 执行接口只接受刚生成的预览 ID 和完全一致的候选 ID 集合，扫描和预览均在五分钟内有效。预览只消费一次；新扫描清空旧预览。前端选择变化使确认失效。
- 每次移动前再次检测已知 Codex GUI/CLI 进程；查询失败也不执行。运行中停止整个剩余批次，并给出跳过回执。
- 每项移动前核对固定根的设备/inode、路径无符号链接，以及文件设备/inode、大小、创建/修改时间和链接数。变化项跳过，独立项仍有各自结果。
- `FileManager.trashItem` 是路径操作。上述校验和进程检测是尽力防护，不是与其他进程之间的原子锁；不保证消除恶意并发替换或启动竞态。
- 执行时协调系统清理的其他操作，并沿用关闭/退出等待策略。只读扫描可取消；已经确认的清理保留 owner 至回执产生，关闭面板不能取消已接受的移动。
- 回执只在 Augma 应用支持目录保存最近一份 JSON（目录 0700，文件 0600），不读取或记录文件内容。首次写入执行意图失败则不移动任何文件；每项移动前写入状态待核实，移动后持久化结果。保存失败停止后续项并显示警告。
- 重新打开可恢复最近回执。进程中断后，未确认完成的项保留“状态待核实”，提示检查原目录及废纸篓。回执中的路径仅供展示，不作为重试授权。

## 验证

夹具覆盖完全匹配确认、重复提交、过期预览、根替换、符号链接、文件变化、运行中阻止整批、部分成功/失败、执行前/后回执写入失败、中断回执恢复、关闭等待及恢复最近结果。测试只移动临时夹具，不执行用户 Codex 数据清理。


本轮验收通过：

- 全量 Swift 测试 415 项，8 项依赖环境而跳过，零失败；显式启用元信息扫描与真实已安装 Mole 的 Codex 专项 24 项全部通过。
- 原生临时窗口实际点击默认零选择、勾选一项、预览、返回不执行、再次确认、系统 Trash API 成功移动及逐项回执。只移动 1 MB 临时缓存；未选日志与受保护哨兵哈希保持一致。临时宿主已按 PID、执行路径和启动时间核对退出。终端读取废纸篓中测试文件的哈希受系统隐私权限阻止，未变更权限；移动由系统 API 返回目标路径及界面回执确认。
- 通用 Release 构建并以与既有安装相同的开发签名更新本机 Augma，严格签名检查及原 designated requirement 通过。旧包与完整资料快照保留在独立本机备份目录。
- 实际安装完成扫描、单项勾选、预览、确认页和执行：当前 Codex 正在运行，原生活动检测阻止移动并持久化“已跳过”回执。所选文件内容/inode 均未变化；既有 77 份资料和偏好哈希不变，只新增权限为 0600 的最近回执。保留日用 Augma 运行，无临时验收宿主遗留。
- `pnpm lint`、`pnpm typecheck`、226 项前端单测、`pnpm build`、三语言字符串表、增量 Swift 格式及 diff 空白检查通过。Web 构建仍有既有大块体积提示。
