# Codex 占用分析与清理预览

> 本文记录首版只读预览及其验收。后续新增的执行功能见[清理执行记录](2026-11-05-codex-storage-execution.md)。

日期：2026-11-05。范围：Augma 原生扫描、待审阅候选、只读预览与可选 Mole 占用复核。Craft Hub 继续拥有项目/worktree 上下文；本功能不引入另一份项目管理或清理执行器。

## 入口与流程

系统监控 → 清理磁盘与内存 → Codex 占用与清理预览 → 分析 Codex 占用 → 查看清理候选 → 手动勾选 → 生成 Codex 清理预览。没有自动扫描、默认选中、后台轮询、AI 请求、删除、移入废纸篓或写入数据库。新类型与已有 `CleanupCandidate`、废纸篓执行入口分离；预览不构成删除授权。

原生分析只读取已知目录中的文件元信息，不解析文件内容。首版检查 `~/Library/Caches/Codex/Default` 和 `~/Library/Application Support/Codex` 中明确列出的 `Cache` / `Code Cache` / `GPUCache` 叶子，以及 `CODEX_HOME/log`、`CODEX_HOME/logs`。不会读取整个 Chromium profile，也不解析配置文件中的自定义日志目录。`CODEX_HOME` 默认 `~/.codex`，显式覆盖必须是绝对路径，不能落在已知受保护范围；无效覆盖不会静默回退。

会话、历史数据库及 WAL/SHM、工作树、归档、生成图片、产物与可视化不在首版扫描根中。即使固定叶子内出现会话、数据库、凭据或持久浏览器状态名称，也跳过而不递归。未知 profile、未列出的缓存路径及其他数据不作零占用或可清理结论。

## 统计与预览合同

- 每个根单独分配 5,000 项、0.8 秒和 24 层的合作式预算；在文件操作之间检查时间和取消。单个阻塞的系统调用不能由此硬中断。
- 拒绝符号链接根，不跟随内部链接或跨卷。普通文件按设备/inode 去重。逻辑大小不等于实际分配量、整个 Codex 的占用或净释放量；APFS 克隆等仍可能重复计量。
- 缺失、无法读取、不完整和完整分开显示。任何中途失败或超预算的根都不提供候选；其他根仍独立完成。安全排除的内容不计入合计。
- 只有至少 7 天未修改且未新建、无硬链接的普通缓存文件或 `.log` / `.log.N` / `.log.N.gz` 文件能成为候选。名称规则只是待审阅依据，不证明数据可丢弃。每根最多展示最大的 100 项并报告省略数量。
- 扫描拥有独立 ID。预览只接受本次已展示候选的 ID，五分钟后无法再次生成；生成前重查根身份、文件设备/inode、大小、修改/创建时间和链接数。新扫描和选择变化清空预览；取消忽略迟到结果；文件变化使再次生成失败。已显示的预览始终只是本机审阅记录，没有执行权限。
- 视图沿用系统清理 Store 的操作协调。关闭面板或退出时取消只读请求，忽略迟到结果；不会中断其他已经接受的清理写操作。

## 可选 Mole

复用既有 `MoleToolClient` 的受支持版本检测、固定 `analyze --json <scope>`、45 秒期限、4 MiB 输出上限与报告验证。不会安装、升级或调用 `clean` / `purge` / `optimize`。当前适配版本仍为 1.64.0；其他版本保留原生分析并显示不兼容信息，不扩大既有版本许可。

Mole 只接收一次完整原生扫描中的已知叶子。调用前再次检查根身份、扫描有效期及该范围内是否新增受保护文件或链接；不把 `CODEX_HOME` 或 profile 根传给工具。此重查仍是尽力校验，不承诺跨进程原子快照。

Mole 报告单独展示时间、来源和逐项完整性；不与原生大小相加，不产生候选，不更改选择，也不把 `partial`/`unavailable` 的数值解释成完整零占用。未安装、版本不兼容、超时、错误或取消均不影响原生结果。

## 实现与验收

代码位于 `apps/mac/Sources/AugmaDesktopDemo/SystemMonitor/Cleanup/CodexStorage{Models,Scanner,Store,Section}.swift`，测试为 `CodexStorageTests.swift`。夹具覆盖受保护范围、符号/硬链接、按根预算、候选上限、缺失与不可读、覆盖目录、过期/旧 ID、文件变化、Mole 调用前范围重查、缺失/未知版本、迟到请求、操作协调和窄/宽深浅色渲染。

真实用户目录只做显式启用的元信息扫描；真实已安装 Mole 仅分析临时日志夹具。没有执行清理。手工使用时，当前页面可展示预览，实际删除仍不在本版范围。

本轮验证结果：

- 全量 Swift 测试执行 407 项，11 项按环境跳过，零失败。单独显式运行本机元信息扫描及已安装 Mole 的临时夹具分析：29 项全部通过。
- `pnpm lint`、`pnpm typecheck`、226 项前端单元测试、`pnpm build`、三种语言的字符串表检查、增量 Swift 格式检查及 `git diff --check` 通过。
- `./script/build_and_run.sh --package` 生成 arm64/x86_64 通用 Release 包，严格签名检查通过；旧包保存在本轮临时证据目录，未启动或替换日用实例。
- 从当前 Debug 模块链接的独立原生验收窗口，实际点击完成：显式扫描 → 初始零选择 → 展开并勾选一项 → 生成 1 项预览 → 选择日志范围 → 真实 Mole 只读分析。复核后候选与选择保持不变；缓存、日志及受保护哨兵文件的 SHA-256 全部未变化。
- 原生验收脚本通过 `finally` 和信号处理保底退出，记录并核对 PID、执行路径、启动时间后确认临时 App 已退出。夹具、PNG、状态及清理 JSON 留在本轮系统临时目录，未提交用户数据。

## 日用安装与 Release 主窗口走查（2026-11-05）

在 macOS 26.6.2 上，将通用 Release 包更新到既有的用户 Applications 安装。先完整备份原安装、应用支持目录和偏好，再使用与原安装相同的既有开发签名身份签署新包；新安装通过严格签名检查，并满足旧安装的 designated requirement。保留旧包与资料快照，不导出 Keychain 凭据，也不修改用户数据路径。新版最低系统为 macOS 26，本轮不能证明 macOS 15 兼容性。

- 原生扫描统计到约 62 MB 的已知缓存与诊断日志，四个已有范围正常显示；该值不是整个 Codex 占用。
